# PlayerState 已确认设计总览

实现更新：P1 已实现 L1 三分支数据校验及标准初始玩家，P2 已接入二维运动；死亡/复活转换和动作接收仍待后续阶段。见 [P1](l1/p1-world-foundation.md) 与 [P2](l1/p2-physics.md)。下方历史描述以此为准。

最新补充（2026-10-26）：[物理与药效 P/F/V 方案](physics-effects-confirmation.md)已由用户整组采用，含输入/求解/承载/击退、来源编码、效果应用与新增阶段设计；[具体数值](rules/physics-effects-parameters.md)已按证据分层补入目录，对应旧“待讨论”描述以这两份文件为准。物理/效果处理器尚未实现，R 未全核实；35/45/55 阶段仍是设计，运行调度代码未改。

更新：2026-10-26。

已接受的 [W06 同批资源规则](decisions/0013-world-engine-and-state.md)：击杀者本批次也死亡时，对应铁/金/钻石/绿宝石直接销毁，不掉落，击杀归属和统计保留；先固定所有死者转移前资源，再统一清空并分别结算，防止循环转移。存活接收/溢出及无击杀者的死亡位置分支照旧，完整死亡处理器尚未实现。

本文汇总用户已接受的数据归属与行为，详细依据见各决策记录。当前没有相应引擎或数据类实现；以下是逻辑结构，不是完整字段全集、类型定义或冻结的外部 API。

## 公共外层

| 内容 | 已确定职责 |
| --- | --- |
| 玩家身份与队伍关联 | 本局死亡/复活期间保留 |
| `life_index` | 首次出生为 1，仅成功复活时加 1 |
| `stats` | 普通 `kills` / `deaths` 与最终 `final_kills` / `final_deaths`，互斥计数并跨复活保留 |
| `progression` | `armor_tier`、`shears_unlocked`、`pickaxe_tier`、`axe_tier`；镐斧保存当前可恢复等级，未购为空 |
| `cooldowns` | 按组保存 `ready_at`；组规则指定死亡清除或保留，保留组等待期间继续计时 |
| `life` | `AliveState`、`RespawningState`、`EliminatedState` 三种互斥分支 |

本局购买进度、统计与跨局模型参数、优化器和训练进度分别管理；创建或重置玩家生命不能隐式重置学习状态。

## 存活分支的逻辑内容

| 内容 | 已确认表达 |
| --- | --- |
| 空间 | 方块边长为 1，水平 `(x, z)` 取矩形中心，向上为正的 `y` 表示脚底，身体范围 `[y, y + H]`；正式增加竖直运动，前期允许纯平面实验；朝向与移动独立，保存必要击退速度信息，具体字段类型待定 |
| `vitality` | `health` 与 `absorption` 分开保存 |
| `inventory` | 物品/变体键到非负整数数量的映射，四种资源同表，受等效堆叠容量约束 |
| `held_item` | 背包物品键引用或为空，不重复计数 |
| `effects` | 基础字段 `effect_id`、`effect_type`、`source`、`level`、`expires_at`、`next_trigger_at`，具体类型/可选值待定 |
| 动作 | `movement` / `interaction` 双通道；基础 `ActionState` 七字段为 `action_id`、`kind`、`target`、`params`、`started_at`、`progress`、`phase` |
| 当前生命受击归因 | `last_attacker_id`、`last_attacked_at`；复活清空，窗口与有效攻击等细则待定 |

玩家之间可互相穿过，仍受方块碰撞约束。主动运动即时响应；击退持续衰减，反向移动只能少量削弱且不能使其停止或反转，具体运动公式仍待定。

正式采用平面加高度的 B 方案，地形为三维方块网格；前期严格俯视二维 A 实验限制单一行走层、无上下重叠通路。二维界面不等于严格二维物理。脚底高度参考点和竖直范围已确定，身体尺寸、碰撞细节、地形底层存储与其余实验机制范围仍待定，见 [0003](decisions/0003-grid-terrain-continuous-players.md)。

碰撞已接受完整碰撞体的路径检查、表面接触合法与贴面滑动；B 中落地/撞顶截断受阻位移并清零对应竖直速度，击退也受方块约束。具体求解器、角落/多面接触、容差、承载与水平击退残余状态仍待定，物理尚未实现。

首期位置/速度等连续运动量采用 binary64，时间继续整数 tick；显示截断不写回状态，快照保证浮点往返恢复，禁止 NaN/无穷。以固定程序版本和运行环境下重放一致为首期验收目标，跨平台逐位一致另验。完整字段/快照编码与碰撞容差仍待定。

## 等待复活与淘汰

| 分支 | 已定基础字段与语义 |
| --- | --- |
| `RespawningState` | `died_at`、`respawn_at`；剩余时间派生，普通死亡进入此分支即表示本次复活已获准 |
| `EliminatedState` | `eliminated_at`、`reason`；已定原因类别为 `final_death`，具体死因/击杀者/位置归死亡事件 |

普通死亡结算时，床仍在则获准本次复活，床已毁则淘汰。等待期间丢床不取消本次复活；复活后下一次无床死亡才淘汰。同一时刻破床/死亡的先后顺序尚未确定。

死亡终止双通道并丢弃未完成进度，清理本生命临时效果。旧生命动作/效果事件执行前须校验存活分支、生命序号和实例有效性；已发射世界实体按自身规则继续运行。物品与资源按分类结算，不将整个背包原样复制到新生命。

首版每张地图每队一个固定出生点及初始朝向，同队开局/复活共用。复活击退速度清零，手持配置的默认木剑；默认物品须存在于本次生成背包。出生区域覆盖完整出生矩形并对所有队伍禁建，承载地形不可被拆除或炸毁。保护范围/边界尚未确定，地形保护不授予玩家伤害或击退免疫。

## 派生数据

- 穿着防具由 `armor_tier`、规则表与团队升级按头/胸/腿/脚派生，不维护独立可变装备表，也不进入普通背包或占用其容量；首版不支持独立脱装/换装或防具耐久。
- 最大生命、背包占用、剩余等待/效果/冷却时间、总击杀/死亡与比值等从源状态和规则派生。
- 地形安全性按位置与地图查询，不在玩家中维护独立 `is_safe` 真值；死亡事件可记录结算判定结果。

## 尚待收敛

- 数据类与具体类型、ID/物品键/等级/空值编码、动作阶段和目标结构。
- 方块碰撞、地形底层存储/文件格式、水平轴正向/原点/地图范围与越界、身体尺寸/数值容差、击退公式、物理积分及完整阶段处理；正式 B 和 A 单层地图限制已选，A 其余实验范围和接口兼容方式待定。坐标、单位、脚底参考点、binary64 与首期复现目标已确定，平台 tick 与排序基础见 [0012](decisions/0012-team-core-types-and-ordering.md)。
- 容量、冷却组、伤害/护甲、药效和等待时长等规则目录及参数；未知值不作为 0、关闭或无限处理。
- 防具/工具具体材质与属性映射、木剑以外初始物品、拾取/转赠与购买记录的关系、其他接收顺序、死亡批次具体类型/实现；批次先计划/校验后一次提交已接受。同批击杀资源按种类汇总后绿宝石→钻石→金→铁接收，同种按固定死者顺序记账；资源接收资格已确认：有效归属的击杀者同批死亡/等待复活/淘汰则销毁不掉落；已复活且批次后存活则交当前新生命背包，统计归来源玩家，旧动作/效果仍按生命隔离。
- 观测/隐藏信息的具体范围与编码、策略故障原因码、训练接口和断线/重连；策略备用取消、被动席位及终局/截断方向已按 [0015](decisions/0015-world-schedule-replay-failures-and-training.md) 采用。
