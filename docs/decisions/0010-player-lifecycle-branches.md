# 0010：PlayerState 的互斥生命周期分支

日期：2026-10-25  
更新：2026-10-26  
状态：用户已接受三种互斥分支、公共数据归属、生命序号/旧事件校验、等待复活与淘汰基础字段、普通死亡复活资格保留、空间初始化及出生保护，首版每队一个固定出生点；具体数据类、完整字段和生命周期执行尚未实现。

## 选择

`PlayerState` 的 `life` 使用三种互斥分支，同一玩家同一时刻只处于其中一种状态：

| 分支 | 主要承载内容 |
| --- | --- |
| `AliveState` | 当前生命的位置、生命值、背包、手持选择、临时效果和动作 |
| `RespawningState` | 本次死亡与计划复活的仿真时刻，以及等待信息 |
| `EliminatedState` | 永久淘汰的仿真时刻与原因类别，不再执行正常行动 |

玩家身份、队伍、本局统计和跨死亡购买进度保留在 `PlayerState` 外层，不随生命周期分支的替换而丢失。购买进度仍按 [0005](0005-inventory-and-progression.md) 更新，例如已购镐/斧死亡降级；“保留在外层”不表示所有数据在死亡时原样不变。

`progression` 已确定 `armor_tier`、`shears_unlocked`、`pickaxe_tier`、`axe_tier` 四个基础字段；工具字段保存当前可恢复等级而非历史最高档，未购为空，具体类型和规则映射见 0005 的待定事项。

实际穿着防具由 `armor_tier`、规则表和当前团队升级按部位派生，不作为 `AliveState` 的独立可变装备表，也不进入普通背包或占用容量；首版不支持独立脱装/换装和防具耐久，复活按源状态重新查询。具体属性映射仍待设计，见 0005。

`cooldowns` 也归公共外层，按 [0008](0008-cooldowns-and-protection-effects.md) 的冷却组规则在死亡时清除或保留；保留组沿原截止时刻计时，等待复活不冻结，复活不重新计时。具体各组的处理方式尚待选择。

用户后续在 [0005](0005-inventory-and-progression.md) 选择显式手持状态：`AliveState.held_item` 引用背包物品键或为空，不复制数量或属性。合法切换瞬时完成、不占持续通道；重复选择不变，切走中断需持续持物的交互，不终止移动或重置冷却。耗尽/移出时清空，无效切换保留原选择和交互，购买/拾取不自动切换；开局/复活生成装备后按配置手持木剑，不继承旧生命选择。具体类型、指令编码及同刻时序仍待细化。

逻辑结构如下，尚不是完整字段表、Python 实现或版本化消息格式：

```text
PlayerState
  玩家身份与队伍关联
  life_index
  stats
  progression
  cooldowns
  life: AliveState | RespawningState | EliminatedState
```

## 生命序号与旧事件校验

[W06 死亡批次提交](0013-world-engine-and-state.md)已采用：每名玩家的生命转换、清理/进度/冷却、资源、统计和复活安排在临时计划中合并成一份最终更新，与掉落物、调度任务及 ID 进度校验后一起提交；本批失败不提交且停止推进，此前阶段恢复归 W12。完整生命周期事务尚未实现。

用户选择在 `PlayerState` 公共外层保存 `life_index`，区分同一玩家的不同生命：

- 首次出生的生命序号为 `1`，每次成功复活加 `1`。
- 死亡、等待复活和永久淘汰不递增，保留刚结束生命的序号；未成功完成的复活不能提前增加序号。
- 同一局内 `player_id` 标识玩家，`(player_id, life_index)` 标识某一条生命。跨局记录仍需通过既有对局标识区分，不能只用这两个值关联不同对局。
- 本生命的动作、效果延迟事件绑定对应的玩家与生命序号；执行前同时检查玩家仍处于 `AliveState` 且生命序号匹配，不满足时不得将其作用到当前生命。
- 已发射到世界中的投射物等实体继续按自身规则运行，不因来源生命结束而自动销毁；不能把本生命动作/效果事件的校验套到这些实体上，取消其正常世界行为。

例如，第 2 条命遗留的回血事件不能作用于第 3 条命。玩家已进入等待复活或淘汰状态时，即使序号尚未改变，也不能继续结算其本生命动作/效果事件。

生命序号校验是必要条件，不替代动作实例、效果实例是否仍有效的检查；同一条命内动作取消、替换或效果刷新后的旧事件，仍需依据既有实例身份与有效性处理。完整快照需要保留生命序号，恢复同一对局状态不能把它误当成首次出生重新编号。具体数值类型、编码和事件调度实现仍待设计。

## RespawningState 的基础时间字段

用户接受死亡后等待复活的 `RespawningState` 保存以下两个基础字段：

| 字段 | 含义 |
| --- | --- |
| `died_at` | 本次死亡的仿真时刻 |
| `respawn_at` | 本次计划复活的仿真时刻 |

剩余等待时间由 `max(0, respawn_at - 当前仿真时刻)` 派生，不维护另一份独立倒计时。两个字段使用同一仿真时间基准，不以墙钟或渲染时间驱动；具体时间类型、单位与编码尚未确定。

只有成功构造新生命时才递增 `life_index`。普通死亡的本次复活资格按下节在死亡结算时确定，等待期间丢床不取消；不能在倒计时归零时再以当前床状态否定已经获得的资格。等待时长数值、实际复活构造与调度细节仍待设计。

死亡位置、击杀归属等保存在死亡事件中；复活装备依据外层更新后的 `progression` 按既定规则恢复，不在等待分支保留可执行的旧存活状态。这里确定的是死亡后等待的基础字段，断线/重连和首次出生前的表达仍待设计。

复活调度属于生命周期事件，不套用前述仅允许 `AliveState` 执行的本生命动作/效果事件条件；具体调度校验与同一时刻的转换顺序尚未确定。

## 普通死亡的本次复活资格

用户接受在普通死亡结算时，根据当时的己方床状态确定本次复活资格：

| 死亡结算时的床状态 | 处理 |
| --- | --- |
| 床仍存在 | 进入 `RespawningState`，获得本次复活资格 |
| 床已摧毁 | 进入 `EliminatedState` |

等待期间床被摧毁，不取消已经获得的本次复活，不重置既定复活等待。玩家完成本次复活后仍可参战；其下一次死亡时，因无床而进入淘汰分支。

因此普通死亡对应的 `RespawningState` 本身表示本次复活已经获准，不额外维护独立的 `can_respawn`。等待中的玩家不能仅因丢床被当作永久淘汰者；队伍参赛/淘汰已在 [0011](0011-team-state.md) 确定为按成员生命分支派生，世界胜负与同时全灭的终局判定仍待设计。

本选择参照规则参考 BW-LIFE-01、02、04、05。BW-LIFE-04 的依据是 2017 年 v0.3 官方历史说明，不表示已核实现行版本的全部边界。同 tick 按已接受的 0012/P/F/V 顺序，50 破床先于 60 死亡；这是平台工程约定，不是 Hypixel 内部精确时序的核实结论。断线/重连等其他流程另行设计。

## EliminatedState 的基础字段

用户接受 `EliminatedState` 保存以下两个基础字段：

| 字段 | 含义 |
| --- | --- |
| `eliminated_at` | 永久淘汰的仿真时刻 |
| `reason` | 导致永久淘汰的原因类别 |

目前已确定的原因类别为 `final_death`，对应导致玩家永久淘汰的死亡；其他原因类别随相应机制确定后补充。`reason` 的具体类型与编码仍待设计，本次不据此启用额外淘汰途径。

`reason` 表达为何结束参赛生命周期，与近战、坠落等具体死亡方式分别记录；击杀者、死亡位置和具体死因仍归死亡事件，不在淘汰分支重复维护这些字段。无有效击杀者也不改变最终死亡这一生命周期分类。

淘汰后本局统计和购买进度继续保留在公共外层，`life_index` 保持刚结束生命的序号。等待中丢床不取消本次复活，不能因此将已获准的等待者转为 `final_death`。

## 复活时的空间初始化

用户选择首版每张地图为每队配置一个固定出生点及初始朝向，同队成员开局与复活共用该位置和朝向。玩家之间可重叠，其他成员占位不要求增加出生点；首版不引入出生点随机选择。不同地图按各自配置提供出生信息，未来扩展多个出生点时另行设计选择规则。

用户接受复活构造新存活分支时按以下规则初始化空间状态：

| 数据 | 初始化规则 |
| --- | --- |
| 位置 | 使用地图配置的己方出生位置，坐标表示玩家轴对齐矩形的中心 |
| 朝向 | 使用出生点配置的初始朝向 |
| 击退速度 | 清零，不继承上一条命的残余击退 |

本节确定复活时的三项空间初始化，不设置具体坐标、朝向数值或速度类型。用户后续已在 [0003](0003-grid-terrain-continuous-players.md) 选择玩家可互相穿过，因此其他玩家占据出生位置不阻止复活，多人可以共享出生位置；不需要为玩家占位而延迟或另选落点。出生区域通过下节禁建约束防止玩家放置方块封堵，承载地形通过保护规则避免被拆除或炸毁；保护范围/边界、地图配置格式和同一时刻事件的完整结算顺序仍待讨论。

复活时清零残余击退与存活期间停止主动移动分别处理：后者仍不能清空有效击退，见 [0003](0003-grid-terrain-continuous-players.md)。生命、装备、临时效果、动作和冷却继续遵守各自已确定的复活与跨死亡规则。

## 出生区域禁建

用户选择方案 A：地图划定出生禁建区域，禁止任何队伍在其中放置方块，避免通过玩家建造堵住出生位置。

- 禁建范围须覆盖配置出生位置对应的完整玩家矩形，不只覆盖中心点。
- 禁建区域属于地图约束，不在每个 `PlayerState` 重复保存。地图、规则与玩家碰撞体尺寸需使用一致的几何约定，并提供初始合法出生位置。
- 所有队伍均受该放置限制约束；放置合法性检查由引擎执行，禁建区域内的方块放置不能成功，物品继续遵守成功放置才扣除的规则。
- 禁建区的具体形状、范围、边界相交判定及配置格式随地图设计确定，不默认整个基地都禁建。

本节确定放置限制，承载地形的保护见下节。规则参考 BW-WORLD-02/03 的现行 Hypixel 保护范围仍待核对，本选择是本项目已采用的地图规则，不作为线上精确范围的证据。

## 出生点承载地形保护

用户接受对出生点的承载地形提供保护：地图标记的该部分原始地形不能被拆除，也不能被爆炸破坏，使出生位置持续具有合法支撑。

保护归地图约束，具体范围和边界由地图配置确定。拆除与爆炸的地形更新需要遵守保护标记；禁建区域与承载地形保护各自表达其职责，不能从出生保护推导整个基地地形不可破坏。

保护对象是地形。玩家伤害、击退与复活保护仍按各自规则处理；地形免于破坏不直接授予其中玩家伤害或击退免疫。该选择不固定地图其他部分的拆除或爆炸规则，也不设定任何保护时长数值。

## 状态约束

- 生命周期状态由当前分支表达，不再独立维护可能与分支矛盾的存活/等待复活/淘汰标记；需要查询时从分支派生。
- 当前生命的有效空间、生命、背包、手持选择、临时效果和动作归存活分支；等待复活或永久淘汰分支不保留仍可参与正常世界更新的旧存活状态。
- 死亡结算必须先取得需要的死亡位置、资源和归因等数据，再按既定规则完成转移、清理、计数及分支转换；精确调度顺序继续待设计。历史数据可进入事件/回放记录，不作为另一份可执行的存活状态。
- 复活构造新的存活分支，遵守既有生命、装备和临时效果规则；动作通道为空，不自动恢复上一条命的动作，见 [0009](0009-movement-and-interaction-channels.md)。位置和朝向取首版每队唯一出生点配置、击退速度清零；保护范围/边界等细节待设计。
- 本局玩家状态与模型、优化器等跨局学习状态分别管理；本决策不改变已确认的持续学习需求，也不决定策略会话记忆的重置方式。
- 公共外层冷却按组规则死亡清除或保留，不因生命分支替换而一律清空；保留记录继续使用原仿真截止时刻。

当前生命的最近攻击者及对应时刻按 [0004](0004-death-resources-and-statistics.md) 管理，不能因公共身份保留而让旧生命的归因信息延续到复活后的生命。

## 与规则和接口的边界

这是本项目的数据组织方式，不是 Hypixel 的内部数据结构。规则参考 [BW-LIFE-01–06](../rules/hypixel-bedwars.md#2-床死亡与复活) 区分存活、等待复活与永久淘汰；本决策已选择普通死亡复活资格的取得与保持，不补定等待时间数值、保护或同一时刻的事件排序。

已有普通死亡等待复活分支不能仅因床被摧毁改为淘汰，这是已采用的模拟规则；现行 Hypixel 的完整边界核对仍是独立事项。自然终局、时限截断与玩家生命状态分别处理，临时死亡也不自动等同于训练接口的 Agent termination。

内部生命周期分支不意味着向所有参赛智能体公开完整分支内容；观测、错误反馈和训练数据继续遵守既有信息边界。

## 后续验收

以下是实现时需要增加的验证，不是已通过的测试：

- 一个玩家同时只持有一种生命周期分支，派生状态与实际分支一致。
- 死亡转换后，旧生命的位置、效果和动作不再作为有效存活状态更新；死亡所需数据只结算一次，历史记录可追踪。
- 等待复活与永久淘汰分别表达，均不执行正常存活动作；复活后构造符合既有规则的新存活状态。
- 身份、队伍和本局统计跨转换保留，购买进度按死亡分类规则更新，恢复装备不复制旧背包。
- 生命周期保存/恢复后保持一致，模型参数和训练进度不因玩家死亡或复活被重置。
- 首次出生序号为 1，仅成功复活递增一次；死亡/等待/淘汰不递增，保存恢复不重编号。
- 本生命的动作/效果事件要求存活分支与生命序号同时匹配；旧生命事件、等待复活中的旧事件及同一生命已失效实例事件不能错误结算。
- 已发射实体不因来源玩家死亡或复活被上述校验自动销毁，仍执行其独立世界规则。
- 等待复活时保存死亡和计划复活的仿真时刻，剩余时间派生；成功复活才递增生命序号，保存恢复不按墙钟重建倒计时。
- 普通死亡时床仍在则获得本次复活资格，床已毁则淘汰；获准等待期间丢床不取消本次复活，也不重置复活时刻，完成复活后下一次无床死亡才淘汰。
- 等待分支与本次资格一致，不维护相矛盾的独立 can_respawn；同一时刻破床/死亡的测试在结算顺序确定后补齐，当前不预设结果。
- 永久淘汰保存仿真时刻与原因类别；`final_death` 与死亡方式/击杀归属分别表达，相关细节仍在死亡事件中，外层统计/购买进度和刚结束的生命序号继续保留。
- 复活位置使用所选己方出生点配置且表示矩形中心，朝向取出生点初始朝向，击退速度为零；不继承旧生命空间状态，不将复活清零规则用于存活期间停止移动。
- 出生位置已有其他玩家时不阻止复活或改变出生位置，允许玩家矩形重叠；方块碰撞约束仍有效，出生区域由禁建规则避免放置封堵。
- 出生禁建区域覆盖完整出生矩形，任意队伍均无法在区域内成功放置方块；失败不扣除方块物品，范围与出生位置/碰撞体尺寸一致。
- 地图标记的出生承载地形在拆除和爆炸更新中均不被破坏；地形保护不错误地授予玩家伤害或击退免疫，出生位置保留合法支撑。
- 首版每队恰有一个地图配置出生点，同队玩家开局与复活共用其位置和初始朝向；重叠不阻止出生，不因重复复活引入额外出生点随机选择。
