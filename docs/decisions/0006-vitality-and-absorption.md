# 0006：普通生命与吸收生命

2026-10-26 补充：[物理与药效 F01–F10](../physics-effects-confirmation.md)已整组采用，更新本文对应的类型/到期/周期/来源/治疗等设计；[参数资料](../rules/physics-effects-parameters.md)区分官方历史、兼容参考、候选及未知。本文其余待核验机制仍保留，尚无完整效果实现。

日期：2026-10-25  
状态：用户已接受的生命状态设计；伤害、吸收和复活重置尚未实现。

## 背景

细化 `PlayerState` 的生命信息时，用户接受分别保存普通生命和吸收生命，并按类型进行伤害与复活处理。本记录是本项目的设计选择；[规则参考 BW-COMBAT-01、Q11](../rules/hypixel-bedwars.md) 中尚未核实的数值继续待核对，不由本决策补成 Hypixel 实测值。

## 已确定

| 数据 | 含义 |
| --- | --- |
| `health` | 当前普通生命值 |
| `absorption` | 当前剩余吸收生命，如金苹果提供的额外生命 |

- 最大生命值由规则及相关生效效果计算，不额外维护另一份固定上限真值。
- 普通可吸收伤害先消耗 `absorption`，余量再扣除 `health`。
- 吸收生命耗尽本身不导致死亡；普通生命耗尽时触发死亡结算。
- 复活时普通生命恢复到复活规则下的上限，吸收生命清零。
- 虚空等特殊死亡机制另行定义，不自动认定所有伤害都能被吸收。

生命上限、吸收量、持续时间及伤害数值不设默认值；数值类型、精度和舍入方式也仍待设计。

## 对 PlayerState 的影响

`vitality` 属于当前生命状态，与跨死亡保留的统计和购买进度分别管理。后续用户已在 [0010](0010-player-lifecycle-branches.md) 确定生命周期分支，生命信息归 `AliveState`；具体数据类和整个生命周期结构仍未实现。

对已进入普通可吸收伤害处理阶段的非负伤害量 `D`，先消耗不超过当前吸收量的部分，剩余伤害再作用于普通生命。护甲、附魔、保护和特殊伤害在此前或此后的计算顺序，继续随战斗规则确定，不由本记录指定完整伤害公式。

吸收剩余量保存一份。其效果来源、到期时刻和到期清理方式需与临时效果模型共同设计，避免在效果表中再维护另一份独立的剩余吸收量。

死亡结算沿用 [0004](0004-death-resources-and-statistics.md)，不能因多次检查生命耗尽而重复转移资源或计数。复活只按此处重置生命数据，不重置模型参数、训练进度、本局统计或已确定的购买进度。

用户后续已在 [0007](0007-temporary-effects.md) 确定本生命临时效果死亡清空。自然回血、复活保护或受击间隔仍未确定。仅消耗吸收生命的攻击是否刷新击杀归因，也需在有效攻击判据中细化。

## 后续验收

以下是实现时需要增加的验证，不是已经通过的测试：

- 伤害小于、等于、大于剩余吸收生命时，依次消耗两类生命，余量计算一致。
- 仅耗尽吸收生命不触发死亡；普通生命耗尽只触发一次死亡结算。
- 复活时普通生命恢复至生效上限，吸收清零，本局统计与购买进度保持对应规则。
- 保存/恢复当前生命与效果所需状态后，后续伤害结果可复现。
