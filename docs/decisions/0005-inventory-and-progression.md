# 0005：携带物品与跨死亡购买进度

日期：2026-10-25  
更新：2026-10-26  
状态：用户已接受物品数量表、容量、分类与手持规则、progression 四个基础字段及派生防具视图；背包、手持、购买进度、防具查询和复活恢复尚未实现。

## 背景

用户在细化 `PlayerState` 时接受按类别处理物品死亡行为，并区分当前携带物品与本局跨死亡保留的购买进度。

设计参考 [BW-ITEM-01](../rules/hypixel-bedwars.md#6-装备与工具持久性)，其中包含官方历史与社区候选资料。本记录是本项目接受的模拟规则，不表示所有行为已经在 Hypixel 最新线上版本实测。

## 背包数量表

用户选择以物品数量表表示背包，概念上为物品标识到非负整数数量的映射；不模拟具体槽位、快捷栏位次或拆分/合并堆叠操作。正式类型、物品标识与变体属性格式尚未确定。

四种资源也由同一数量表记录。需要单独展示资源时，从表中派生资源视图，不再维护一份独立钱包。购买、拾取、使用和死亡结算都更新对应的唯一数量来源。

属性不同且需要区分的物品应使用可区分的物品标识或变体键，不能仅因显示名称相同就合并。手持物通过下节的背包物品键引用表达；穿着防具采用后文派生视图，不作为普通背包物品。具体物品键格式继续待设计。

用户已选择按等效堆叠限制容量，不采用无限携带。具体参数仍待确定，不设置默认总容量或默认堆叠上限；满容量处理见下节。

## 显式手持状态

用户选择方案 A：在 `AliveState` 中保存 `held_item`，引用背包物品键或表示为空；切换手持物品会更新该状态。

- `held_item` 只保存引用，不复制物品数量或属性；数量仍由 `inventory` 唯一记录，属性由物品定义及对应变体提供。
- 有效的非空手持引用须对应实际携带的物品，不能仅因已购买过、`progression` 中已解锁就视为当前持有。
- 手持引用不会额外增加一份物品或容量占用，背包继续采用数量表，不引入具体槽位或快捷栏位次。
- 该状态供相应动作、快照、回放与后续观测使用；具体动作如何使用/切换物品与参赛者可见信息仍需遵守各自契约。

具体类型、空值编码、可手持物品目录与切换指令编码仍待落实；20 阶段控制与 40 阶段购买的先后已按 W08 采用，见下节。库存变化与开局/复活初始选择已按下节确定。

## 手持切换规则

用户接受以下一组规则：

- 合法切换为瞬时更新，不单独消耗仿真时间，也不占用持续动作通道；重复选择当前物品不产生变化，不因此中断原交互或重置进度。
- 饮药、进食、拆块等交互需要持续手持对应物品；切换离开该物品时中断对应交互，丢弃未完成进度。切回物品不会自动恢复已中断动作。
- 尚未完成的物品使用不因切换中断而提前扣除；已成功结算的状态继续遵守 [0009](0009-movement-and-interaction-channels.md) 的不回滚规则。
- 切换不终止移动，不重置物品或动作的冷却；既有 `ready_at` 继续按各组规则判断。

本节确定切换耗时、通道归属和上述交互影响。后续 [W08](0013-world-engine-and-state.md) 已确定每玩家每轮最多一次切手，20 阶段按转向→切手→移动通道更新→交互通道更新处理，40 阶段结算购买；新购物品不能用于本轮更早的切手，购买不自动切换或重试，需下一轮另令。零耗时不免除物品持有与可手持条件的合法性检查，合法切手导致的中断不因后续请求失败撤销；具体编码与未列动作细节仍待落实，尚未实现。

## 手持耗尽、无效切换与初始化

用户接受以下处理：

| 情况 | 处理 |
| --- | --- |
| 当前物品仍有余量 | 保持 `held_item`，不因数量减少而改变选择 |
| 当前物品耗尽或被移出背包 | 清空 `held_item`，不自动换成其他物品 |
| 切换到不存在或不可手持的物品 | 拒绝切换，原手持与原交互保持，仍接受正常合法性检查 |
| 购买或拾取物品 | 更新背包，不自动改变手持；原本空手时也不自动选中 |
| 开局与复活 | 生成本次装备后选择规则配置的默认手持物品，首版为木剑，不继承上一条命的选择 |

成功使用最后一件物品不因其数量归零而被回溯判为失败。例如最后一瓶药水完成使用时，在一次完整更新中扣除物品、施加效果并清空手持；本次完成后的空手状态不撤销已成功结算的结果。

默认手持物品必须存在于当次生成的背包，配置校验需检查该条件；首版初始装备配置因而需要提供对应木剑。木剑的具体物品键和其他初始装备继续随物品目录及规则配置确定，本节不补定整套初始装备、数量/容量数值或自动补发武器机制。

这些是本项目已采用的模拟规则，不能据此认定现行 Hypixel 的手持自动选择、购买替换或补发行为已核实。20 阶段控制与 40 阶段购买的顺序已按 W08 采用；W09 已补 32 地面拾取阶段，未列动作结算细节继续落实。

## 等效堆叠容量

每种物品按其数量和规则配置的堆叠上限折算容量占用，不同物品标识或变体键分别计算：

```text
占用容量 = Σ 向上取整(物品数量 / 该物品堆叠上限)
占用容量 ≤ 总容量
```

堆叠上限为正整数；总容量及各物品上限的具体值待确定并在规则配置中校验。此计算按数量折算已合并的等效堆叠，不新增真实槽位或堆叠位置数据。

占用容量由数量表和规则计算，不在 `PlayerState` 中维护另一份独立真值。穿着防具不进入普通背包数量表，也不占普通背包容量。涉及多项物品增减时，容量检查需要考虑完整变更后的数量，不能只看新增物品。

购买、拾取和击杀接收的容量边界按以下已确定规则处理；复活恢复的配置合法性与特殊边界继续另行设计。

## 满容量处理

用户接受以下规则：

| 操作 | 容量不足时 |
| --- | --- |
| 购买 | 整次失败，不扣费、不发物品 |
| 地面拾取 | 能装多少装多少，余量留在原地 |
| 击杀获得四种资源 | 尽量装入，余量在击杀者当前位置掉落；该处不安全则销毁余量 |

购买容量按扣费并加入商品后的完整数量表检查，因为支付资源可能腾出容量。校验失败时不提交背包或购买进度的部分变化。

部分拾取只扣除地面物品中实际接收的数量。[W09](0013-world-engine-and-state.md) 已采用 DroppedItemState 八个基础字段与数量提交：背包增加/地面减少一起提交，数量归零移除实体，拾取不自动改变手持，类型与处理器尚未实现。击杀接收时，死亡者清空的资源分别进入击杀者背包、生成溢出掉落物或销毁，不能重复结算；背包已有堆叠仍有余量时应纳入可接收量计算。

击杀接收溢出的掉落位置是击杀者的当前位置，与无有效击杀者时依据死者死亡位置的规则分别处理。两者均使用 0004 的地形安全定义，不回退到历史安全位置。

2026-10-26 已接受的例外见 [W06](0013-world-engine-and-state.md)：击杀者本批次也死亡时，对应四种资源直接销毁、不生成掉落，击杀统计保留；该情况不进入满容量溢出流程。先固定本批死者转移前资源，再统一清空并分别结算，避免循环转移。

跨生命接收已确认：有效击杀归属/统计归来源玩家，资源按本批结算后生命状态处理；等待复活/已淘汰则销毁、不掉落，已经复活且仍存活则进入当前新生命背包并按现有容量/溢出规则处理。独立投射物结算不恢复旧背包或旧动作/效果。

同批击杀资源的容量分配已确认：同一击杀者的多笔资源先按种类汇总，再按绿宝石 → 钻石 → 金 → 铁尽量接收，计入已有堆叠余量；一种装不下仍检查后续类型，不自动丢弃原物品腾位。同种资源按固定死者顺序分配接收/溢出明细，不改变击杀归属；溢出继续按击杀者当前位置安全性掉落或销毁。此优先级是平台规则，具体容量/堆叠上限仍由规则表给出。

生成器分享是单独的实验规则：触发者取自己能容纳的地面数量 q，合格队友最多接收 q 且各受自己背包容量约束；额外份额装不下则不发放、不掉落、不补发。地面未取走的余量保留，额外产量按实际所得记账；处理器尚未实现，Hypixel 容量行为待核验。

W09 已补 core 自动拾取、扩张玩家 AABB 检查物品中心、32 当前位置检查与不额外检查视线的实验规则，保留 Hypixel 待核验；具体范围/延迟/寿命数值仍须显式配置。普通掉落物拾取竞争已采用玩家外层 player_order、每玩家按 (created_at, entity_id) 升序，逐笔重查并原子提交实际数量；装不下当前物品仍查后续，余量可由后续玩家接收，不套用击杀资源优先级。生成器分享仍待确认；其他多物品接收/掉落实体的具体顺序、精确掉落几何及事件编码仍待设计；死亡批次先计划/校验后一次提交已接受，事务尚未实现。同批/跨生命接收资格与上述击杀资源分配不重开。

## 已确定的死亡处理

物品使用与动作成功结算的扣除时点已在 [0009](0009-movement-and-interaction-channels.md#物品扣除与成功结算) 确定：饮药/进食完成、方块成功放置、投掷/发射消耗品实体成功生成时分别扣除；主动中断或失败不提前扣除。死亡清理仍按本节分类执行。

| 类别 | 死亡处理 |
| --- | --- |
| 携带的铁、金、钻石、绿宝石 | 按 [0004](0004-death-resources-and-statistics.md) 转移、就地掉落或销毁 |
| 购买的剑、弓、方块、药水等一般消耗品 | 清除，不转给击杀者，不生成掉落物 |
| 已购买的防具升级 | 保留档位，复活时按规则重新派生穿着防具 |
| 已购买的剪刀 | 保留购买记录，复活时恢复 |
| 已购买的镐、斧 | 死亡降一级，最低保留基础级；未购买过则不自动获得 |
| 团队升级 | 在 `TeamState` 中保留，不因单个玩家死亡而重置 |

四种资源的结算与一般消耗品的清除分别处理，不能将资源一并按消耗品直接销毁。箱子内容与当前携带物品分别管理，箱子权限和队伍淘汰时处理继续另行设计。

## progression 的基础字段

用户接受以下四个基础字段，表达本局跨死亡保留的购买进度：

| 字段 | 含义 |
| --- | --- |
| `armor_tier` | 已购买的永久防具升级档位 |
| `shears_unlocked` | 是否已购买永久剪刀 |
| `pickaxe_tier` | 当前可恢复的镐等级，未购买时为空 |
| `axe_tier` | 当前可恢复的斧等级，未购买时为空 |

镐、斧字段保存当前可恢复等级，不是历史最高购买等级；死亡结算时按既定规则降一级，最低保留已购买的基础级，未购买者继续为空。防具升级档位与剪刀购买标记按既定规则保留。

实际携带物品仍归 `inventory`，当前手持选择归 `held_item`，团队升级仍归 `TeamState`。具体档位、材质、附魔及对应价格由规则表定义；基础档位、等级/空值编码和具体数据类型尚未选择。

防具的实际部位与属性需按规则档案确定，不能从“防具升级”直接推导全套同材质。实际穿着按下节派生；物品实例结构以及拾取/转赠与购买进度的关系仍待设计。

## 派生防具视图

用户选择方案 A：根据 `progression.armor_tier`、规则表和 `TeamState` 的团队升级，派生玩家实际穿着的防具视图，不维护另一份独立可变装备表。

- 规则表按头、胸、腿、脚分别映射装备信息，不能把一个升级档位直接当作整套同材质防具；具体材质、附魔及属性值仍待规则目录确定。
- 购买升级自动改变相应派生视图；复活根据保留的档位与当前团队升级重新得到防具信息，不向普通背包额外插入穿着防具。
- 穿着防具不占普通背包容量。防具升级交易更新购买档位，背包仅按交易扣除支付资源；成功扣费与更新档位仍需作为一次完整结算。
- 首版不支持独立脱装、换装或防具耐久；防具视图不单独保存当前穿戴物品清单、耐久或另一份团队升级真值。
- 后续伤害计算可读取该视图；伤害公式、各类减伤的先后顺序、观测可见性和具体查询类型仍待设计。

本节确定本项目首版的防具表达与范围，不表示 Hypixel 现行全部防具细节已核实，也不扩展规定其他物品或工具的耐久行为。

## 对 PlayerState 的影响

- `inventory` 表达当前生命实际携带的物品。
- `AliveState.held_item` 表达当前手持选择，引用背包物品键或为空，与数量表分别承担选择和计数职责。
- `progression` 表达本局跨死亡保留的购买进度；工具等级在死亡结算时按规则更新。
- 复活时根据更新后的进度恢复相应工具、派生防具视图，不把上一条生命的整个背包原样复制回来。
- 团队升级归 `TeamState`，通过队伍关联使用，避免在每位玩家中重复维护一份升级真值。
- 这里的购买进度属于一局世界，不是模型参数、优化器或跨局学习状态。

背包数量表、等效堆叠容量、满容量处理、四种资源唯一数量来源、手持规则、购买进度四字段、防具派生及同批击杀资源分配顺序已确定；装备映射、同刻时序、容量参数、其他接收顺序、物品属性键及计数接口仍待设计。同一份物品或资源不能在多处重复记账。

## 后续验收

以下是实现时需要增加的验证，不是已经通过的测试：

- 一般消耗品死亡清除，不误触发资源转移或掉落。
- 防具与剪刀购买进度跨复活保留；防具重新派生，剪刀按规则恢复到携带物品中。
- 已购镐/斧每次死亡仅降一级，基础级保留，未购买者不凭死亡获得工具。
- 四种资源继续遵守 0004；统计与团队升级不被背包清理重置。
- 重复处理同一生命的死亡，不重复降级或重复生成恢复物品。
- 购买、拾取、消耗和死亡结算使用同一数量表，资源视图与原表一致；数量不能变成负数或因重复记账而复制物品。
- 容量按完整数量表及各物品堆叠上限派生；验证堆叠边界和容量刚好用完的情况。
- 购买按扣费与发货后的结果检查，失败不扣费、不发货、不更新购买进度；支付释放容量的情况可以正确处理。
- 部分拾取后余量留在原地；击杀接收的溢出按击杀者当前位置安全性掉落或销毁，各去向数量与死亡者扣除量一致。
- 手持选择引用实际背包物品键或为空，不复制数量/属性，不额外占容量；保存恢复后保留相同选择，失效引用不得继续被视为有效物品。
- 合法手持切换瞬时完成且不占持续通道；重复选择当前物品不改变动作实例或进度。
- 饮药/进食/拆块中切走会中断对应交互并丢弃未完进度，切回不自动恢复；未完成使用不提前扣物，已结算结果不回滚。
- 切换不终止移动，也不重置物品/动作冷却的原截止时刻。
- 当前物品有余量时保持选择，耗尽或移出背包时清空；后续购买/拾取不自动选中或恢复手持。
- 无效切换不改变原手持或中断原交互，原动作继续遵守自身合法性条件。
- 使用最后一件物品成功时，扣物/施加对应结果/清空手持作为完整更新，不因数量归零撤销本次成功。
- 开局/复活生成装备后按配置手持木剑，不继承旧生命选择；默认物品未生成时配置校验不能通过。
- 购买进度按四个已定字段保存/恢复；镐斧降级更新当前可恢复等级，不误用历史最高档，未购买时不因复活获得工具，防具/剪刀进度按规则保留。
- 防具视图由档位/规则/团队升级一致派生，各部位分别映射；购买或复活不向普通背包插入穿着防具，不增加容量占用，不维护独立装备或耐久状态。
- 防具升级按成功交易扣资源并更新档位；生效视图随当前档位和团队升级变化，不因重复保存派生装备而失去同步。
