# 0008：主动冷却与保护效果分别管理

日期：2026-10-25  
状态：用户已接受数据归属、冷却在玩家公共外层保存及按组配置死亡处理；具体类型、规则参数、冷却与保护行为尚未实现。

## 已确定

用户接受主动操作冷却单独保存，保护状态复用 [EffectState](0007-temporary-effects.md) 的划分。

- `cooldowns` 放在 `PlayerState` 公共外层，按冷却组保存再次可用的仿真时刻，概念形式为 `cooldowns[group] = ready_at`；不随存活/等待复活等生命周期分支替换而整体丢失。
- 需要模拟的受击保护、复活保护等，作为各自的效果类型放在 `effects`，复用实例标识、来源及到期时刻。
- 不在 `PlayerState` 再维护同一保护的独立截止时刻或倒计时；保护是否有效由效果记录与具体规则查询。

冷却控制自己何时能再次发起操作，保护决定怎样处理受到的伤害，两者不能混成同一个计时状态，也不能直接用击杀归因的最近受击时刻代替。

## 按冷却组配置死亡处理

用户选择由每个冷却组的规则指定死亡处理方式：

| 方式 | 行为 |
| --- | --- |
| 死亡清除 | 死亡结算时移除该组冷却记录 |
| 跨死亡保留 | 保留原 `ready_at`，等待复活期间仿真时间照常推进 |

保留的冷却在复活时继续依据原截止时刻判断，不重新开始计时，也不冻结等待期间的时间。继续计时通过原 `ready_at` 与当前仿真时间比较实现，不维护独立剩余倒计时。

死亡处理方式归冷却组规则，不在每位玩家的冷却记录中再重复维护一份策略。具体哪些组清除、哪些组保留，随动作和物品规则逐项确定；未知组不自动采用任一默认处理方式。具体类型与编码仍待设计。

## 规则边界

本次确定的是数据归属，不表示已确认 Hypixel 目标版本启用了哪些主动冷却、保护或时长。具体动作与物品的共享冷却组、触发时机、时长和伤害适用范围仍待核对；未核对值不自动按 0、关闭或无限处理。

保护复用效果记录，不套用等级型增益的取最高等级算法。不同保护可有各自的伤害类型、解除条件及优先关系；如需要额外过程数据，按对应类型设计，不把它强行编码成效果等级。

保护的到期时刻使用 `EffectState.expires_at`；非周期保护不需要下一触发时刻，非等级保护的等级表示与可选值编码仍待设计。内存与消息格式都沿用基础接口的数据隔离要求。

本生命临时保护沿用效果死亡清理规则。复活时是否施加何种保护及其具体参数仍由复活规则定义；主动冷却按上节已接受的组规则处理，具体各组取值尚未确定，不能从临时效果清理推导全部冷却清零。

## 后续验收

以下是实现时需要增加的验证，不是已经通过的测试：

- 主动冷却不错误地替代伤害保护，保护不错误地占用主动冷却组。
- 保护记录只有一个到期时刻来源，查询与快照恢复一致。
- 不同保护按各自规则判断伤害与解除，不自动按等级型增益合并。
- 冷却和保护都使用仿真时间，网络或策略耗时不驱动其倒计时。
- 冷却位于玩家公共外层，死亡仅按组规则移除或保留；等待复活的分支转换不误清除保留组。
- 保留组的原截止时刻在死亡、等待与复活过程中不重置或冻结，等待期间已到期的冷却不会在复活后重新开始。
- 不在玩家记录中重复维护组死亡策略；保存恢复截止时刻后查询结果一致。

## 未解决
