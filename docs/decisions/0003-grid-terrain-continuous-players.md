# 0003：方块网格、玩家连续移动与矩形碰撞体

日期：2026-10-25  
更新：2026-10-26  
状态：用户已接受空间表示、攻击朝向约束、速度式击退及玩家之间可互相穿过；正式方案采用平面加高度（B），前期允许严格俯视二维（A）实验。数据结构、运动、碰撞和攻击尚未实现。

## 背景

细化 `PlayerState` 时，需要明确方块网格是否也限制玩家只能处于格点。用户在逐格移动与连续移动两种方案中选择了后者：方块使用网格组织，玩家位置可以在格子内部连续变化。

随后用户选择以轴对齐矩形作为玩家的平面碰撞轮廓，并以矩形中心作为玩家平面位置的参考点。后续用户接受平面加高度作为正式方案，并允许前期先做严格俯视二维实验；坐标、高度参考点与首期 binary64 浮点方案已在下节确定。`WorldState` 与 `PlayerState` 完整字段仍待设计，后续已在 [0010](0010-player-lifecycle-branches.md) 确定玩家生命周期分支及公共数据归属。

## 选择

- 方块按网格单元组织，建造与拆除定位相应的网格位置。
- 玩家使用连续空间位置，不要求位于格心或格点；移动不能简化为在离散格子间直接跳转。
- 玩家所在格子由连续坐标与明确的转换约定派生，不分别维护两套独立的位置真值。
- 玩家平面碰撞体采用轴对齐矩形：边与方块网格坐标轴平行，不随玩家朝向旋转。是否使用等边尺寸与具体边长尚未确定。
- 玩家连续平面位置以矩形的平面几何中心为参考点；坐标、单位、网格边界与浮点表示采用下节约定，水平轴正向、原点、地图范围/越界规则和数值容差仍待确定。
- 距离与碰撞需要基于连续位置及选定的碰撞体计算。网格可用于寻路或候选查询，实际移动仍需遵守连续空间中的碰撞规则。

## 正式高度方案与前期二维实验

用户确认：“采用 B，但是前期可以先做 A 的试验。”本次 A/B 对应下列空间方案，与此前进程接入等讨论的选项编号无关。

- **正式方案 B：平面移动加高度。** 平面连续位置之外表达高度与竖直速度，并为起跳、腾空、落地及不同高度的通行提供物理基础；地图需表达承载面与竖直阻挡。界面可以采用二维俯视展示，但物理状态增加第三个运动自由度，不能称为严格二维物理。
- **前期实验 A：严格俯视二维。** 允许先在仅有平面位置的模型中实验，降低早期验证成本；这不取代正式 B，也不表明 B 的跳跃、竖直碰撞或立体建造已经完成。
- 平面矩形及中心参考点等已接受约束继续适用。高度与坐标参考点采用下节约定，正式地形采用三维方块网格、A 实验限制单一行走层；底层存储、身体尺寸与碰撞细节，以及 A 实验的其余机制范围和 A/B 接口兼容方式，继续共同讨论；本次不冻结完整数据结构或协议。
- A 中尚未定义的跳跃类效果不能自动解释为空操作或已验证的 Hypixel 行为。是否暂不提供相关物品、是否另设实验适配，均需明确实验范围后确定；此前关于具体药效应用方式的建议尚未因此全部采用。

这是一项分阶段设计选择，本次仅记录决策，没有实现 A 或 B 的物理处理器。

## 坐标、单位与高度参考点

用户已接受以下整组约定，属于本平台的空间建模协议，不作为 Hypixel 内部坐标实现已核实的证据：

| 内容 | 已确定约定 |
| --- | --- |
| 长度单位 | 一个方块边长为 `1` |
| 水平平面 | 使用 `(x, z)`，玩家位置取轴对齐矩形的平面中心 |
| 高度 | 使用 `y`，向上为正，表示玩家脚底高度 |
| 玩家竖直范围 | 身体高度记为 `H`，范围由脚底高度派生为 `[y, y + H]` |
| A 实验阶段 | 先处理平面运动与碰撞 |
| B 正式阶段 | 加入竖直速度、重力、起跳和竖直碰撞 |

玩家三维位置可概念性表示为 `(x, y, z)`，其中水平分量 `(x, z)` 为矩形中心，竖直分量 `y` 为脚底；不把 `y` 误作身体中心。身体中心高度可由 `y + H / 2` 派生，不保存第二份独立位置。内部数值表示采用下节已接受的 binary64 方案。

具体身体尺寸、移动/起跳速度、重力及其他物理参数仍待规则核对；方块整数坐标与连续空间的转换采用下节的半开网格与 floor 约定，地图范围/越界规则与接触数值细节仍待确定。前期 A 与正式 B 共用上述平面坐标约定，但完整接口兼容方式继续待设计。

## 地形结构与 A 实验地图范围

用户已接受以下整组地形方案：

- 正式地形采用**三维方块网格**，每个方块由整数格坐标定位，支持表达多层桥梁、悬空结构与逐块拆建，不采用每个平面格子仅一个地面高度的高度图作为唯一地形真值。
- 三维网格确定逻辑表达，具体采用稀疏字典还是分块存储，连同文件格式、地图尺寸/边界和查询接口，仍待决定；不因采用网格而认定全部格子或全部方块类型具有相同碰撞形状。
- 前期 A 实验限制为**单一行走层、没有上下重叠通路**的测试地图，先验证平面移动、碰撞与击退。正式 B 再加入竖直运动与多层通行；A 的实验结果不作为这些高度机制已完成的证据。
- 床继续按 [0011](0011-team-state.md) 作为特殊地图对象关联 `TeamState.bed_state`，不因采用三维网格而复制第二份床存亡状态。防御方块归普通可变地形。

地形网格存储、A 的具体高度配置与其余实验机制仍待确定；网格边界与碰撞行为采用以下约定，精确碰撞算法与数值细节尚未确定。地图与物理处理器尚未实现。

## 网格边界归属与坐标转换

用户已接受以下整组网格约定：

- 整数格 `(i, j, k)` 对应单位区域 `[i, i + 1) × [j, j + 1) × [k, k + 1)`，依次对应 `x`、`y`、`z` 轴。
- 网格区域左闭右开；恰好处于整数边界时，归入由该整数开始的格子。
- 位置参考点所在格通过 `(floor(x), floor(y), floor(z))` 派生，使用向下取整，负坐标也遵守同一规则，不能以向零截断替代。例如 `x = 1.0` 属于第 `1` 格，`x = -0.2` 属于第 `-1` 格。
- 玩家占用与碰撞候选查询必须检查完整碰撞体覆盖的格子，不能只查位置参考点所在格。脚底所在格不直接等于承载玩家的方块。
- 半开区间用于确定格子归属；身体与方块仍按表面接触合法、穿透受阻的碰撞规则判定，不能把两种用途混为一谈。

这组约定不决定地图实际覆盖范围、是否包含负坐标区域、越界后的行为或具体方块碰撞形状。碰撞数值容差与候选格枚举的精确实现仍待设计，不据此宣称已有物理代码。

## 内部数值表示与首期复现目标

用户已接受首期采用 **64 位浮点（IEEE 754 binary64）** 及以下整组约定：

- 时间继续使用整数 tick；位置、速度等连续运动量使用 binary64 浮点。首期 Python 运行环境需满足该浮点格式，完整字段类型与其他规则量另行定义。
- 界面显示或文本展示的小数截断不写回世界状态，不通过展示精度改变运动过程。
- 快照保存足够精度，保证浮点数往返恢复；具体快照编码格式尚未冻结。
- 世界状态禁止 `NaN` 和正负无穷值，不能将其作为位置、速度或未配置参数的占位值。
- 首期以固定程序版本和运行环境下的重放一致为验收目标；跨平台逐位一致另行验证，不能仅因采用 binary64 而宣称已保证。
- 碰撞容差采用下节已接受的原则，具体数值与实现仍待确定；选择浮点表示不等于已经采用某个容差值，也不改变既定的网格 floor 归属。

这是平台工程选择，不作为 Hypixel 内部数值类型或物理参数已核实的证据。Python 浮点的舍入与表示限制见 [Python 官方说明](https://docs.python.org/3/tutorial/floatingpoint.html)。本次仅记录设计，尚未实现物理状态、快照或重放验收。

## 碰撞容差原则

用户已接受以下整组原则：

- 容差由引擎统一定义，随物理配置版本记录。
- 对本次已检测到的接触，将容差范围内的微小位置误差沿接触面法线修正到表面；修正只影响受阻方向，保留切向位移。
- 网格转换直接对当前坐标取 floor，不额外加容差改变格子归属。
- 距离容差、速度判零阈值与碰撞时间容差分别定义，按各自单位处理，不能混用一个无量纲 epsilon。
- 具体数值等地图范围、身体尺寸与求解器确定后，通过边界测试选定；不将待定值自动解释为零。

例如落地后脚底存在极小数值误差时，可修正到接触地面；普通运动坐标仍保存完整精度。上述原则不授权用容差掩盖真实穿透，也不确定异常地图/出生位置的修复方式。

## 移动路径碰撞与贴面滑动

用户已接受以下整组碰撞行为，先在 A 实验中验证平面部分，正式 B 再扩展到竖直碰撞：

| 情况 | 已确定行为 |
| --- | --- |
| 接触方块表面 | 允许贴墙、站在地面上；身体不能穿入实体内部，朝表面内部的运动仍受阻挡 |
| 斜向撞墙 | 阻挡朝墙内的位移，保留沿墙方向的位移，形成贴面滑动 |
| 一步位移较大 | 检查玩家完整碰撞体沿运动路径扫过的范围，不能只检查终点或只检查中心点，从而避免穿墙 |
| B 中落地或撞顶 | 截断对应方向的位移，并清零被阻挡的竖直速度 |
| 击退撞到障碍 | 同样受碰撞约束；击退主导规则继续用于未被障碍阻挡的运动 |

例如向东北移动时东侧有墙，仍可沿墙向北移动，不因东向受阻而整步停止。玩家之间仍不互相阻挡，不能把此处方块碰撞规则误用为玩家身体阻挡。

这是已接受的行为原则，不等于已经选定具体求解器。多面同时接触/角落处理、路径扫掠与数值容差、水平击退残余速度的碰撞后处理、承载判定，以及与起跳/台阶的关系仍需细化；身体尺寸与规则数值仍待核对。本次未实现或验证物理处理器。

## 对 PlayerState 的影响

`spatial` 需要表达连续位置、用于攻击约束的当前朝向，以及速度式击退所需的跨步运动状态。移动与朝向独立，因此当前朝向不能仅由速度方向推导；静止时也保留朝向。主动移动速度可由当前动作与规则计算，击退所需速度信息需持续保存；位置/速度等连续量采用 binary64，正式字段与其余具体类型仍待设计。

移动目标、路线与游戏动作进度应与当前位置分别表达。若某运动量影响下一步结果且不能由其他状态唯一推导，需进入可恢复的状态；能唯一计算的派生量无需独立维护。

碰撞体形状、尺寸、移动速度等规则参数与当前坐标分别管理。只有模型确实允许这些参数在局内变化时，才增加相应的可变状态。

矩形的边界根据中心位置和尺寸推导，无需额外维护一份独立的位置或四角坐标。以平面中心 `(x, z)`、沿两轴的边长 `w` 和 `d` 为示意变量：

```text
min_x = x - w/2    max_x = x + w/2
min_z = z - d/2    max_z = z + d/2
```

上述变量不固定最终字段名称。表面接触合法、阻挡穿入、路径检查与贴面滑动采用上节行为；具体数值容差、承载判定和多面接触求解仍待设计。玩家之间不互相阻挡，见下节。

## 玩家之间可互相穿过

用户选择方案 A：玩家之间可互相穿过，玩家仍受方块碰撞约束。

- 玩家矩形可以彼此重叠，不因另一玩家占位而阻挡移动，不通过身体接触产生推挤；该规则适用于队友和敌人。
- 正常主动移动与击退运动都不因其他玩家身体占位而停止，仍须遵守各自运动规则和玩家与方块的碰撞约束。
- 多名玩家可以共享出生位置，其他玩家占位不构成复活阻挡，也不需要为此等待或寻找备用位置。用户后续已在 [0010](0010-player-lifecycle-branches.md) 选择出生区域禁建，防止放置方块封堵，且承载地形不可被拆除或炸毁；具体保护范围/边界仍待确定。

不互相阻挡只确定身体占位与运动规则，不取消玩家矩形在攻击命中、距离和其他空间查询中的作用，也不取消攻击造成的伤害与击退。投射物命中、重叠玩家的目标选择和多目标结算仍按各自后续规则设计，不能从可穿过推导免疫或自动命中。

这是本项目的二维模拟选择，不表示 Hypixel 现行玩家碰撞机制已核实。

## 攻击朝向约束

用户选择攻击受朝向限制：攻击动作的合法性需要考虑玩家朝向，不能只因满足距离等其他条件就忽略朝向要求。具体允许角度、各类攻击的适用方式及检查时刻仍待设计；本次不设置默认角度。

朝向参与游戏规则，但不旋转轴对齐矩形碰撞体。用户已选择瞬时转向：朝向可以直接更新到目标方向，不单独消耗仿真时间，也不设置有限角速度来逐步转身。因此不因转向过程增加角速度、转向进度或转身倒计时状态。

用户已允许侧移与后退：移动方向和朝向独立，移动不强制角色面向前进方向；停止移动后仍保留朝向，单独转向不自动旋转已有运动方向。控制输入采用世界方向还是相对朝向的方向、执行器如何组合移动和瞄准，仍待设计。

同一轮内转向与攻击的结算顺序，以及战术执行器怎样转向和瞄准，仍需细化。瞬时转向不取消其他动作的耗时、冷却或攻击条件。

该选择不定义自动命中，也不替代距离、遮挡、冷却等其他攻击条件。爆炸、延迟命中等机制如何应用方向要求，需要在对应机制中分别定义。

## 主动移动即时响应

用户选择主动移动即时响应：明确改变移动方向、目标速度或停止主动移动时，不模拟主动运动的起步、停步和改向加减速过程。主动速度可由当前动作与规则计算，不因主动惯性额外保存独立的速度历史或加速进度。

即时响应不表示瞬间到达移动目标；位置仍随仿真推进，并受速度上限、碰撞和已确定的击退主导约束。明确停止主动移动只消除主动运动贡献，不能清空仍在延续的击退状态。

用户后续在 [0009](0009-movement-and-interaction-channels.md) 确定正常决策轮未更新通道时继续原持续动作；这与明确停止主动移动分别处理。算法异常、超时或必需输入漏交另定，不能由即时响应推导其处理方式。基础速度、速度修饰、斜向移动、输入参考方向和具体合成规则继续待定。

## 速度式击退

用户选择击退通过速度变化表达：受击改变运动速度，随后持续移动并逐渐衰减。不能只把一次受击转换成单次位置跳变而丢弃后续运动过程。

因此世界状态需要保存足以延续击退过程的速度信息，快照恢复也需恢复该状态，不能只恢复位置或初始随机种子。

用户确认受击期间仍允许主动移动，同时要求：“移动无法抵消击退的效果，即使相反方向移动，击退的效果也会占主要效果。”因此，主动操控不能取消击退，运动合成需要保持击退主导；不能在未定义控制约束时直接采用任意主动速度与击退速度的简单相加。

用户进一步明确采用“允许少量削弱”：反向移动可稍微降低击退造成的运动，但不能因主动操控使击退停止或反转，击退仍占主导。具体削弱幅度、侧向操控强度、恢复正常控制的条件和碰撞响应尚未确定。上述约束针对主动操控，不意味着击退可以绕过碰撞规则，也不限制尚未定义的连续受击更新。

主动速度按当前动作与规则计算，击退所需速度信息持续保存；正式字段及其保存形式、受约束的运动合成方式、连续受击叠加或覆盖、方向和幅度、衰减方式及参数、碰撞响应和停止条件，均继续待定。本次不默认任意控制权重、限幅系数、衰减公式或参数。

## 收益与成本

该表示可在同一网格内区分玩家位置，支持连续距离和位移的建模。相应地，需要实现玩家与方块的碰撞、坐标到网格的转换、边界处理及跨越多个网格单元的移动检查。

连续空间本身不保证跨平台逐位复现。首期已选择 binary64 与固定版本/运行环境下重放一致的目标；运算顺序、物理积分和碰撞容差需共同设计与验证，不能将该选择当成已通过确定性验收。

以下是实现时需要增加的验证，不是已通过的测试：

- 玩家位置可以取同一网格内的不同坐标，不被强制吸附到格心。
- 跨格移动遵守半开网格与 floor 约定，整数边界和负坐标向下取整结果一致；玩家位置参考点所在格、完整碰撞体覆盖格与承载方块分别查询。
- 贴墙或站在地面表面合法，朝实体内部的位移受阻；斜向撞墙保留切向位移，单步较大位移检查完整碰撞体沿途范围，不能穿过中间障碍。
- B 中落地或撞顶截断对应方向位移并清零被阻挡的竖直速度；击退同样受方块约束，不因其主导性穿墙。角落与同时接触等精确行为待后续细化后验证。
- 队友或敌人占位均不阻止玩家通过，重叠不产生身体推挤；玩家仍受方块碰撞约束，正常攻击的伤害/击退不因此被取消。
- 出生位置已被玩家占据时仍可复活，多人可共享该位置；出生区域内的放置操作按禁建规则拒绝，精确边界待确定后验证。
- 朝向变化不会旋转玩家的轴对齐矩形碰撞体；边界由位置与尺寸一致地推导。
- 攻击发起由引擎按约定检查朝向；允许角度边界和检查时刻需在规则确定后验证。
- 朝向更新不经过有限转速的过渡或额外转身等待；更新后的攻击仍按约定结算顺序校验其他条件。
- 支持保持面向目标的同时侧移或后退；停止移动不清空朝向，单独转向不自动旋转已有运动方向。
- 明确改变主动移动意图后即时响应，不产生额外的主动加减速过渡；停止主动移动后，剩余击退仍按规则延续。
- 击退产生后续持续运动及衰减；保存并恢复击退中的状态后，按相同规则和动作继续得到一致的运动结果。
- 受击期间允许主动操控，反向输入可少量削弱，但不能让击退停止或反转；待具体控制约束明确后，验证自由空间中的击退主导及碰撞边界行为。
- 建造、拆除、距离判定与观测使用一致的坐标定义。
- 水平运算使用 `(x, z)`，`y` 向上且表示脚底；身体中心与竖直范围从脚底和规则高度派生，出生与落地查询不得混用高度参考点。
- 正式地形能在相同平面位置表达不同高度的方块及上下通路；A 实验地图满足单一行走层、无上下重叠通路的限制，不能把投影后的单层地形当作完整 B 地形。
- 连续运动状态满足 binary64 与有限值约束；快照往返恢复原浮点值，展示精度不改变内部状态；在固定程序版本/运行环境下验证重放一致，跨平台逐位一致单独验证。
- 保存和恢复必要运动状态后，在同配置、实现版本及动作下继续产生一致结果。
