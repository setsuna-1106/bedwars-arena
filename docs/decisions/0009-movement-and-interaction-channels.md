# 0009：移动与交互双通道

日期：2026-10-25  
状态：用户已接受基础 `ActionState` 七字段、双通道、持续执行、替换、物品结算时点、死亡动作清理和执行条件失效时中断；具体类型、指令时序和执行行为尚未实现。

## 已确定

用户选择将玩家动作执行分为两个通道：

- `movement`：移动执行状态。
- `interaction`：攻击、拆块、饮药等交互执行状态，同一时刻只执行一项交互。

移动可与一项交互并行，支持边移动边攻击。并行不免除距离、碰撞、朝向、冷却、物品等合法性检查；各动作类型的具体限制和耗时仍待设计。

已确定的瞬时转向不占用持续动作通道；[W08](0013-world-engine-and-state.md) 已接受 20 阶段转向→手持切换→移动通道更新→交互通道更新，后续动作读取更新后的朝向/手持，动作实际结算仍按各自阶段。

## 未更新通道时持续执行

用户选择在正常决策轮没有更新某个通道时，保持该通道当前持续动作，直到完成或被中断，不因为没有新指令就停止。

保持的是同一动作实例、目标与已完成进度，不重新开始计时或清空进度。动作完成后不因下一轮没有更新而自动重新发起；购买、物品消耗等一次性结算也不因保持而重复执行。持续动作按自身定义产生的正常过程更新不受影响。

此处只定义正常决策轮未更新某通道的语义；算法软超时、报错或必需动作包缺失时按 [0015](0015-world-schedule-replay-failures-and-training.md) 由 Runner 生成备用取消，不能自动当作正常保持。

## 新指令替换规则

用户接受以下处理：

| 新指令情况 | 处理 |
| --- | --- |
| 与当前持续动作的种类、目标、参数相同 | 保持原动作，不重置进度 |
| 不同且合法 | 中断并替换该通道旧动作，丢弃未完成进度 |
| 无效 | 拒绝新指令，原动作按既有规则继续 |

新指令只影响指定通道，另一通道继续运行；不自动排队。已完成的结算不撤销，物品按下文成功结算时点扣除。

新指令不能被接受时，不先取消旧动作。原动作仍需遵守自身的持续合法性检查，拒绝新指令不豁免原动作的距离、物品等限制。

相同持续动作的保持与一次性操作的请求去重分别处理，不能只因购买内容相同就忽略一次新的购买。显式取消语义已按 W08 采用，见下文；语义参数比较、请求标识/去重具体编码及重新开始的表示继续落实。

## 执行中目标或条件失效

用户选择方案 A：对应动作中断，不暂停保留进度，也不在条件恢复后自动继续。

- 目标已经消失，或目标玩家当前生命结束时，结束以该目标为对象的动作。
- 执行过程中超出该动作要求的距离，或不满足其朝向要求时，即使条件只是暂时失效，也终止对应动作并丢弃未完成进度。
- 条件恢复后必须重新下令；再次执行是新动作实例，不接续此前进度。正常决策轮未更新通道不能重新启动已中断的动作。
- 中断只处理对应动作；其他通道仍按自身条件执行，已完成结算不回滚，尚未完成的物品使用按既定规则不提前扣除。

只检查动作本身实际要求的距离和朝向条件。移动与朝向独立的既定规则不变，不能仅因玩家侧移或后退就判定移动动作失效。攻击等动作定义中的正常冷却等待单独处理，不因冷却尚未结束而套用上述条件失效中断；具体等待阶段、冷却触发及初次接收条件仍待按动作类型定义。

这是本项目的执行设计，不是对 Hypixel 线上行为的新增核实。规则参考 BW-COMBAT-01 的数值与二维表达仍待细化；检查频率、边界相等时的判定、遮挡等未列条件和同一时刻排序尚未确定。反馈继续遵守观测边界，不能借中断原因额外泄露隐藏目标信息。

## 物品扣除与成功结算

用户选择以下扣除时点：

| 操作 | 扣除时点 |
| --- | --- |
| 饮药、吃金苹果 | 使用完成时扣除，同时施加效果 |
| 放置方块 | 成功放置时扣除 |
| 投掷、发射消耗品 | 成功生成对应世界实体时扣除，不等待命中 |

主动取消、替换或操作失败时，尚未完成的使用不扣物品。已经生成的方块、实体或效果不因动作中断而撤销，也不退还物品。成功结算需将物品扣除与对应状态变化作为一次完整更新，仍应校验必要库存与其他合法性条件，不能只有进度达标就无条件施加效果。

死亡仍按 [0005](0005-inventory-and-progression.md) 清理携带物品；主动中断不扣除不意味着死亡后保留一般消耗品。购买继续使用已确定的成功交易同时扣费/发货、失败不变更规则。

本次没有设定动作耗时、物品效果数值或具体耐久规则，未列动作的持续消耗仍需按类型定义。

## 死亡与复活的动作处理

用户接受以下规则：

- 玩家死亡时立即终止 `movement` 与 `interaction`，清空两个通道并丢弃未完成进度。
- 复活后两个通道均为空，由策略重新下达指令，不自动恢复上一条命的动作。
- 已完成的世界变化不因玩家死亡而回滚；已放置方块、已发射实体继续遵循各自规则。玩家本生命临时效果仍按 [0007](0007-temporary-effects.md) 死亡清理，不能把不回滚误解为保留这些效果。
- 动作结束记录保留死亡这一终止原因，供回放与训练数据使用；旧动作实例及其尚未提交的完成事件不能在新生命继续推进或结算。

清空通道不删除历史动作记录；复活后再次提交相同语义的动作时，也不能接续上一条命的实例或进度。已生成世界实体的后续行为与被终止动作的延迟完成分别处理，不能因清理动作而撤销已成功生成的实体。

后续用户已在 [0010](0010-player-lifecycle-branches.md) 确定以 `life_index` 区分不同生命；本生命动作延迟事件执行前校验玩家仍存活且生命序号匹配，动作实例仍需有效。已发射实体不因来源生命结束被这项动作事件校验自动销毁。

这是本项目已采用的执行规则，不是对 Hypixel 线上动作接口的核实。普通死亡复活资格已在 [0010](0010-player-lifecycle-branches.md) 按 BW-LIFE-01–06 的相关证据确定，等待期间丢床不取消本次复活；首版开局/复活共用每队固定出生点与朝向，复活击退清零、出生区域禁建及承载地形不可拆除/炸毁也已确定，出生保护边界和等待时长等仍待设计。冷却已在 [0008](0008-cooldowns-and-protection-effects.md) 确定保存于公共外层、按组规则死亡清除或保留，具体组选择仍待定。本节不决定死亡与动作完成发生在同一仿真时刻的先后顺序。

## 瞬时手持切换与交互

用户已在 [0005](0005-inventory-and-progression.md) 接受手持瞬时切换，不单独耗时、不占持续动作通道，重复选择当前物品不产生变化。

饮药、进食和拆块等交互需要持续手持对应物品；切走时中断该交互并丢弃未完成进度，切回不自动恢复。未完成的使用不提前扣物，已结算状态不回滚；移动继续，物品/动作冷却不因切换重置。

后续 [W08](0013-world-engine-and-state.md) 已确定 20 阶段先转向、再切手、再更新移动/交互通道，40 阶段才结算购买。每玩家每轮转向/切手各最多一次，购买合计最多一笔且不占持续通道，先去重/超限拒绝该组；新购物品须下一轮才能据此切手，购买不自动重试切换。合法切手导致的交互中断不因后续新请求失败撤销；取消编码与各动作未列结算细节继续设计，尚未实现。

后续已在 0005 确定无效切换不改变原手持/交互，原动作继续接受正常合法性检查；物品耗尽/移出后清空手持，购买/拾取不自动选择。成功使用最后一件物品时，完成结果与扣物、清空手持在一次完整更新中结算，不能因清空手持再将本次成功回溯判为失败。

## 显式取消（W08 已采用）

[W08](0013-world-engine-and-state.md) 已确认正常省略通道表示保持，取消须提交明确 cancel 请求并指定自身持续动作通道；取消处理时该通道的当前动作，空通道返回无变化。取消在 20 阶段对应通道更新位置执行，占该通道本轮一次更新；与新动作同时更新同一通道则按冲突规则全部拒绝。

成功取消清空该动作与未完成进度，使关联旧任务失效，另一通道继续，条件恢复后不自动恢复；取消不重置冷却或清除已生效效果。取消移动只停止主动移动，持续击退仍按物理规则运行；取消未完成饮药不扣药，已完成饮药的效果保留。清理与任务失效由引擎统一提交，旧任务不能复活动作。

请求的生命/轮次/封口/去重约束保留；此前转向/合法切手已经导致交互中断时，随后取消空通道不重复终止。已完成交易、已放置方块与已发射实体按原规则保留，不提供一次性购买撤销、执行队列修改或陷阱主动移除接口。具体字段/反馈编码与处理器尚未实现。

## 请求反馈与动作结果（W08 已采用）

[W08](0013-world-engine-and-state.md) 已采用 rejected/accepted/applied/failed 四种请求状态。applied 表示控制请求已成功应用；持续动作之后完成或中断另行记录并关联 action_id，不改写原请求结果。相同动作保持或取消空通道返回 applied 并注明无变化，不产生虚假的动作终止事实；重试不重复执行或产生结局事实。

接收回执可即时给出，执行结果/动作结局只在完整 tick 边界发布，正常随下一轮观测交付；反馈保留实际处理 tick、请求与轮次标识和稳定原因码，整包错误单独反馈。公开原因与关联标识均须遵守观测权限，详细诊断内部保留，引擎故障单独报告；具体 Schema/原因码表/内容比较与接口尚未实现，策略异常/超时/必需输入缺失处置归 W12。

## 数据归属

`spatial` 保存真实位置、朝向和必要的击退运动状态；移动通道表达主动移动的意图与执行信息，不维护另一份独立真实位置。停止主动移动不能清空仍有效的击退。

交互通道保存继续执行所必要的目标、进度和阶段等状态，基础字段见下节。对受工具、急迫等因素影响的持续操作，需要考虑累计工作进度，不能只用开始时刻乘当前速度重建全部历史。

本记录只确定玩家执行通道，不固定高层战术任务到通道动作的映射，也不把模型记忆或训练状态放入动作执行状态。

## 基础 ActionState（字段已确定，待实现）

用户已接受以下七个基础字段及职责，具体类型、可选值、目标表示、阶段枚举与版本化协议仍待细化，没有相应运行实现：

| 字段 | 用途 |
| --- | --- |
| `action_id` | 唯一区分执行实例，保持动作时不变，替换时区分新旧实例 |
| `kind` | 动作种类 |
| `target` | 目标实体、方块、位置或物品等 |
| `params` | 不重复目标字段的其他语义参数 |
| `started_at` | 本次执行开始的仿真时刻 |
| `progress` | 需要累计时保存已完成工作或进度，具体形式按动作类型设计 |
| `phase` | 当前执行阶段，用于组织执行和完成结算等过程 |

不需要累计进度的动作不为此维护一份独立位置或计时真值；具体可选值、进度结构和阶段定义仍待设计。一次性请求标识与执行实例身份的关系也需在去重契约中明确。

`kind`、`target` 和 `params` 表达动作语义，用于判断是否保持当前持续动作；保持时不改变执行实例标识、开始时刻和已有进度。执行实例身份与请求重试身份分别处理，不能把新请求标识当成动作语义变化。

这是引擎维护的运行状态，不等同于外部指令格式。执行实例、开始时刻、进度和阶段由引擎组织与更新，外部策略不能通过提交状态字段直接推进进度、伪造时刻或修改世界状态。

## 调度与边界

两个通道由同一引擎统一结算，不能因每个通道各处理一次而重复推进世界。外部策略仍通过已确定的进程内接口提交数据，Runner 统一组织决策轮。

通道为空的表示、保持/取消/新动作的具体编码、未列中断与完成条件、执行条件检查时序、故障原因码和未列动作的持续消耗仍待落实；异常或必需输入漏交的备用动作原则已按 0015 采用。已列目标/距离/朝向失效时中断、死亡清空双通道和复活不恢复已确定；已投出实体等已完成结算不因当前动作被替换或玩家死亡而撤销，继续按自身规则处理。

## 后续验收

以下是实现时需要增加的验证，不是已通过的测试：

- 移动和符合条件的一项交互可以并行，不因共用一个动作槽而错误互斥。
- 同一时刻不会执行两项互斥交互；相同持续动作保持，不同合法动作只替换指定通道，无效指令不取消旧动作，不自动排队。
- 瞬时转向不错误地占用移动或交互通道。
- 正常决策轮未更新通道时，同一持续动作继续且保留进度；完成后的动作不重新发起，一次性结算不重复。
- 目标消失、目标玩家当前生命结束或执行中不再满足所需距离/朝向时，中断对应动作并丢弃未完进度；条件恢复或未更新通道均不自动恢复，重新下令创建新实例。另一通道按自身条件执行，正常冷却等待不误触发此中断。
- [W06 拆建增补](0013-world-engine-and-state.md)已接受：拆块目标在引擎内部绑定方块实例，多人进度独立不合并；目标移除后其余动作中断，同格同材质重建为新实例，旧进度/完成事件不能继续使用。已拒绝的请求不因地形随后改变而自动恢复。
- 饮药/进食完成、方块成功放置和消耗品实体成功生成时分别扣除；主动取消或失败不提前扣除，已完成结算不回滚且不重复发生。
- 瞬时手持切换不占持续通道；相同选择不影响原动作，切走中断需持续持物的交互且不自动恢复，移动及原冷却截止时刻不受切换重置。
- 死亡时两个通道立即终止、丢弃未完进度并记录原因；复活后无自动恢复，相同语义的新动作也不复用上一条命的实例，旧动作完成事件不能作用于新生命。
- 已放置方块和已发射世界实体不因来源玩家死亡而被动作清理回滚；本生命临时效果仍按既定死亡规则清除。
- 两个通道的执行不重复推进仿真时间，正常执行仍满足既有合法性与信息边界。
- 保存恢复必要动作状态后，在同规则与输入下继续得到一致结果。

## 未解决

动作目录和参数、具体字段类型与目标表示、参数语义比较、保持/取消/重新开始及请求去重编码、故障反馈原因码、未列中断条件与条件检查时序/边界、进度表示与阶段定义、耗时和未列动作的消耗/耐久、冷却触发/等待及各组死亡处理选择、出生保护边界、各类并行限制，以及同一时刻死亡/动作完成等验证与结算顺序。异常与必需输入漏交的备用动作原则见 0015。
