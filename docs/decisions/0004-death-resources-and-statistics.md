# 0004：死亡资源结算、击杀归属与统计保留

日期：2026-10-25  
状态：用户已接受的规则设计；死亡结算、背包与统计尚未实现。

2026-10-26 补充：[W06-B 与同批死亡资源](0013-world-engine-and-state.md)已采用。60 阶段开始确认攻击资格，稳定顺序计算伤害、阶段内最后统一死亡，允许互相击杀。用户明确修正：击杀者本批次也死亡时，对应四种资源直接销毁、不掉落，击杀归属和统计保留；此前在击杀者死亡位置掉落的提案未采用。

跨生命接收也已确认：有效击杀归属/统计归来源玩家，资源接收按本批结算后生命状态判断。等待复活或已淘汰时对应资源直接销毁、不掉落；已经复活且仍存活时交给当前新生命背包，容量/溢出照旧。独立投射物产生新的结算，旧玩家动作/效果仍按 life_index 隔离。

## 背景

细化 `PlayerState` 的死亡清理与复活保留范围时，用户明确要求：“死亡时清空资源，资源交给击杀者，KD这种数据保留”。

本记录确定本项目采用的设计，不把它作为 Hypixel 线上完整资源转移规则的实测证据。原规则的资源归属和死亡转移见 [BW-ECON-02、BW-ECON-04](../rules/hypixel-bedwars.md#4-资源生成器与存储)。

## 已确定

- 死亡时结算并清空该玩家携带的铁、金、钻石和绿宝石；存在有效击杀归属且击杀者在本批结算后仍存活时，交给对应击杀者，受容量限制，超出部分按 0005 的满容量规则处理。
- 存在有效击杀归属但击杀者本批次也死亡、仍在等待复活或已淘汰时，该名死者待转出的四种资源直接销毁，不向任一方死亡位置生成掉落，不写入已结束的生命背包；击杀归属和统计仍保留，不改走无击杀者分支。
- 独立世界实体的有效击杀来源玩家已经复活且本批结算后仍存活时，资源交给当前新生命背包；不恢复旧背包，不因来源生命已经结束就取消独立实体的新结算。前提是对局与该实体仍有效、击杀归属已通过对应规则校验。
- 没有有效击杀者时，若死亡当刻的位置安全，在该处生成这四种资源的掉落物；若位置不安全，直接销毁资源、不生成掉落物。以死亡位置为依据，不回退、搜索或采用最后安全位置。
- 本局击杀、死亡等统计跨死亡与复活保留，不能随当前生命状态一起重置。
- 本次统计保留范围是一局内；跨局汇总、长期玩家档案与训练指标的保存方式继续另行设计。

用户已明确资源仅指铁、金、钻石和绿宝石。常用物品的死亡清除、永久购买进度和工具降级已另在 [0005](0005-inventory-and-progression.md) 确定，不由资源转移规则统一处理。箱子中的物品也需与当前携带资源分别管理。

### 同批死亡的资源批次

已接受的[完整批次提交原则](0013-world-engine-and-state.md)：按对局/玩家/生命去重死亡请求，固定结算依据，在临时计划中合并每名玩家的生命转换、统计、资源、清理/进度/冷却与复活安排；校验引用、生命序号、容量及逐种资源守恒后，将玩家、掉落物、调度与 ID 进度一起提交，再输出事实事件。失败不提交本批并停止推进，此前阶段恢复归 W12。设计已接受，事务尚未实现。

先固定本批所有死者在转移前携带的四种资源，再统一清空并分别计算接收、溢出、掉落或销毁。接收者是否属于本批死亡集合须先确定，不依赖遍历顺序；新接收资源不再次参与本批死亡转移。

例如甲带 4 金、乙带 10 铁并互杀：两份资源全部销毁，位置安全也不生成掉落；双方击杀与死亡照常计数，普通/最终分类依既定生命周期规则。

同批击杀资源容量分配也已接受：同一存活接收者的多笔资源按种类汇总，按绿宝石 → 钻石 → 金 → 铁尽量接收，利用已有堆叠余量且不自动丢弃原物品；一种装不下仍检查后续种类。同种资源按固定死者顺序分配接收/溢出明细，各死者来源独立留账，不改变击杀归属。溢出继续按击杀者当前位置处理；具体容量/堆叠上限仍由规则表提供，地面拾取机制另论。

## 掉落位置安全

用户接受按地形判断安全位置：

- 位于有效地图范围内。
- 非虚空，该处能合法承载掉落物。
- 是否有敌人、属于哪支队伍，不影响掉落判定。

安全性由死亡位置和对应地图状态查询得出，不在 `PlayerState` 中维护另一份独立的 `is_safe` 状态。死亡结算记录可以保留判定结果以供追踪，具体字段待设计。

地图边缘和支撑面的精确几何条件，以及同一时刻地图变化与死亡结算的先后关系，仍随地图和时序契约细化。

## 击杀归属

用户接受以下归因方式：

- 敌方攻击直接致死，归属于该次攻击的来源玩家。
- 受击后坠落或因环境死亡，在归因时间窗口内，归属于最后一次有效攻击的敌方玩家。
- 没有有效攻击记录或已超过窗口，则没有击杀者，按死亡位置进入就地掉落或销毁资源的分支。

多人先后攻击时使用最后一次有效敌方攻击，不按累计伤害最多者归因。例如 A 攻击后 B 再攻击，随后受害者在窗口内坠落，则归于 B。

当前生命的归因记录保存最近有效攻击者和对应仿真时刻，设计字段记为 `last_attacker_id` 与 `last_attacked_at`。复活时清空这些归因信息，本局累计统计继续保留。具体数据类与版本化消息格式尚未实现。

窗口使用仿真时间，长度暂不设默认值，也不解释成无限。窗口端点是否包含、有效攻击的判据、同一时刻多次攻击的排序，以及持续伤害、投射物或召唤物等来源映射继续待设计。

## 对 PlayerState 的影响

统计应放在玩家的本局累计状态中，与当前生命的背包、生命值和临时效果分别管理。后续用户已在 [0010](0010-player-lifecycle-branches.md) 确定三种互斥生命周期分支，统计归公共外层；完整数据类、分支字段和具体类型仍待设计。

用户已选择分别保存四个原始计数：

| 字段 | 含义 |
| --- | --- |
| `kills` | 普通击杀数 |
| `deaths` | 普通死亡数 |
| `final_kills` | 最终击杀数 |
| `final_deaths` | 导致永久淘汰的死亡数 |

同一次击杀或死亡只计入普通、最终中的一类，不能同时增加两类计数。普通与最终的分类依据本次死亡是否导致永久淘汰，由生命周期规则判定；具体同一时刻的结算边界仍待设计。

总击杀为 `kills + final_kills`，总死亡为 `deaths + final_deaths`。普通 KD、最终击杀死亡比及总体比值从原始计数派生，不额外维护一份独立比值；对应死亡数为零时的展示方式仍待确定。四项均放在玩家的本局累计状态中，跨死亡与复活保留。

按 [0005](0005-inventory-and-progression.md) 已选择的物品数量表，四种携带资源也从同一表中结算；单独展示资源时使用派生视图，不维护另一份独立钱包，避免重复记账。

背包已选择等效堆叠容量约束；本批结算后仍存活的击杀者尽量接收资源，装不下的余量在击杀者当前位置掉落，该处不安全则销毁余量，见 [0005](0005-inventory-and-progression.md#满容量处理)。这是存活接收者的溢出，不适用于同批死亡直接销毁分支，也不改变无击杀者时依据死亡位置处理的规则。

为执行归属与转移，引擎还需表示死亡来源、最终确定的击杀归属和对应资源结算。当前生命的最近有效攻击记录与已发生的死亡结算分别管理，不能由资源转移结果反推击杀归属。

死亡结算还需取得死亡当刻的位置；在清理当前生命的空间状态前保留该信息。它可放在死亡事件或结算记录中，具体字段待设计。本规则不要求为资源掉落保存玩家的最后安全位置，也不复用末影珍珠等其他机制的安全位置回退逻辑。

## 实现建议与验收方向

以下是实现时需要细化和验证的内容，不是已实现行为：

- 根据死亡前的携带资源进行一次完整结算，死亡者扣除与击杀者获得保持一致，不重复转移。
- 没有有效击杀者且死亡位置安全时，就地生成掉落物，不额外转移给其他玩家；有有效击杀者时走对应接收或同批死亡销毁分支，不能重复生成同一批资源。
- 死亡位置与历史安全位置不同时，掉落规则只依据死亡当刻位置；无有效击杀者且位置不安全时，资源销毁、不生成掉落物，也不回退。
- 安全位置仅按地形条件判定；更换附近敌人或位置所属队伍，不改变同一地形下的掉落资格。
- 资源从死亡者扣除后，按规则转给击杀者、生成掉落物或销毁，只结算一次；有有效击杀者时不因死者位置不安全改走无击杀者分支。同批击杀者也死亡则直接销毁，存活接收者的溢出依据击杀者当前位置处理。
- 同一生命多次受到致命伤害时，死亡统计与转移只结算一次。
- 击杀者本批次也死亡时，对应资源全部销毁且不生成掉落；双方安全/虚空位置组合和死亡遍历顺序不改变这一去向，统计仍保留。
- 跨生命投射物有效击杀分别验证来源玩家等待复活、永久淘汰与已复活存活：前两者资源销毁且保留统计，后者按当前新背包接收/溢出；旧玩家动作/效果不能因此越过生命校验。
- 直接致死按攻击来源归因；环境死亡分别验证窗口内、超过窗口和无记录的情况；窗口边界在参数与端点规则确定后验证。
- 多人先后攻击按最近有效记录归因；受害玩家复活清空其受害生命的归因记录，旧受害生命记录不用于新受害生命。独立投射物产生的新击杀另按来源玩家及当前资源接收资格处理。
- 复活后本局统计延续；本局累计状态与新生命临时状态分别重建。
- 普通和最终计数互斥更新，总数由两类相加得到；重复死亡结算不导致重复计数。
- 无击杀者、虚空、持续伤害、多人攻击、同时死亡及击杀者背包容量边界按明确规则处理。
- 内部结算的击杀归属与参赛者可见信息分别处理，不自动将隐藏角色的位置等信息加入观测。

## 未解决

完整物品目录及特殊物品行为、掉落位置精确几何判据、归因窗口与端点、有效攻击和伤害来源映射、同一时刻攻击排序、永久淘汰边界、批次具体类型/实现、容量数值、其他拾取/掉落实体顺序、掉落物堆叠/消失、零死亡展示及跨局汇总。同批/跨生命接收资格、转移前固定资源与击杀资源容量分配已接受，不重开。
