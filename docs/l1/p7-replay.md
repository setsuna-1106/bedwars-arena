# L1 P7：输入重放与二维回放

P7 在 P6 Runner 的完整边界记录上增加逐 tick 状态差量、规范状态 SHA-256、输入批次及快照索引；回放重新执行记录输入并比较每个 tick 的世界状态和事实，不重新调用策略。连续碰撞由引擎在运动阶段生成 `movement_collision` 事实，可在回放中定位接触物体和法线，不由界面推测碰撞。

## 运行与查看

```bash
# 新版 Runner 自动记录完整帧及快照索引
bedwars-arena run-l1 --seed 101 --preset examples/l1-controlled-2v2.json \
  --episode-limit 1100 --output artifacts/run-p7 --json

# 从起始快照逐 tick 验证，成功后导出独立离线 HTML
bedwars-arena replay-l1 artifacts/run-p7 --html artifacts/run-p7/replay.html --json

# 从 tick 200 的周期快照恢复到本次 episode 结束
bedwars-arena replay-l1 artifacts/run-p7 --from-tick 200 --json

# 短受控演示：同时覆盖一次回收、失床后死亡与碰撞
python examples/l1-p7-showcase.py artifacts/p7-showcase

# 四个预选样本，分别从 200、400 恢复；A 样本额外从 0 核对
python examples/l1-p7-four-matches.py artifacts/p7-four-matches \
  --existing-a artifacts/run-p7 --limit 650
```

将生成的 `replay.html` 用本机支持 Canvas 和 `structuredClone` 的现代浏览器打开，不需要服务器或网络。`--from-tick` 只核对所选快照及之后的区间；导出的 HTML 仍包含整个记录，如需核对前段，应从起始边界运行一次。画面包括地面、桥、墙、床、地面物品和玩家；顶部显示两队床与成员状态，玩家面板显示 HP、保护、背包、动作和冷却。地图支持缩放、拖动、点击选择及跟随玩家；时间轴提供关键事件标记和前后事件跳转，事件列表可筛选、分页，并支持暂停、单 tick、拖动和变速。状态和事实是记录数据；显示不写回世界。回放是供实验检查的完整状态视图，不作为策略观测。

短演示预置蓝床已毁、蓝方一名玩家低生命，红方一人携带羊毛；它是验证事件与界面的受控片段，不是公平的策略比较。四样本脚本使用 [P6 不对称预置](../../examples/l1-controlled-2v2.json)；E1/E2 或 D1/D2 是同种确定性策略的独立会话，交换席位或种子不构成独立随机策略证据。若达到外部上限则按记录显示截断，不伪称自然终局。

## 记录与恢复

- `initial-snapshot.json`、`final-snapshot.json` 和 `snapshots/` 仅包含完整边界；默认周期为 200 tick。`index.json` 将每个快照的状态哈希、帧文件字节偏移、帧序号、输入/外部补交/轮次/事实游标绑定在一起。
- `rounds.jsonl` 保存原始批量输入的可恢复编码、接收回执和必要的 Runner 备用提交；`inputs.jsonl` 提供可读的策略原始输出、备用原因和回执，并以每轮哈希与输入批次关联。无法 JSON 编码的输入被记录为必然在接口层拒绝的代表；NaN/无穷保留为原始编码以重现拒绝。在 Runner 持有 episode 期间，外部重试或迟到请求通过 `runner.receive_recorded(packet)` 提交，按原顺序写入 `external-inputs.jsonl`；不要直接绕过 Runner 向其世界提交，否则无法保证记录完整。已记录的实际动作和结果只用于核对，绝不作为额外请求重新投递。
- `frames.jsonl` 首帧对应初始快照，之后每个完整 tick 保存规范状态 SHA-256、可恢复差量和日志游标；`events.jsonl` 保留有序事实。验证器先核对定义、代码和运行环境，从所选快照开始恢复输入游标；先核对快照此前的事实与其持久消息记录，每个 tick 再核对接收回执、事实、完整规范状态及末尾结果。发现差异报告首个 tick 和对象路径；日志缺失、游标或版本不匹配则拒绝。
- 现有已封口请求在快照中继续执行，不重复接收；决策间隔大于 1 时根据记录逐 tick 恢复，外部时限仍相对于原 `episode_start_tick`。时间截断后的后续实验须创建新 episode，不把它伪装为同一 episode 的继续。
- 引擎故障时保留最近完整帧；若本边界已接收或封口新输入，另存 `fault-boundary-snapshot.json`，区分它与上一个已校验帧。重放可检查此前完整部分并返回故障信息，不声称失败 tick 或跨版本修复已经重放。运行记录在输出阶段发布；进程在写出前崩溃时不能保证磁盘恢复。

P7 的清单版本为 2，运行时绑定 `l1-p7-3`、包内 Python/JSON 内容哈希和 Python 版本。P6 的旧记录缺少逐 tick 参照，不自动升级为 P7 记录；旧快照在当前代码下会明确拒绝。固定版本和环境中的逐位核对不构成跨平台一致性承诺。训练闭环和 40 局端到端矩阵分别属于 P8、P9。

## 受控试验结果（2026-10-28）

使用 P6 不对称预置和 `101-A` 席位配置，正式 Runner 在 tick 752 自然结束，红队获胜：tick 509 蓝床被玩家破坏，tick 531 和 752 两名蓝方玩家分别最终淘汰；记录中有 6 次购物、22 次放置，策略备用动作 0 次。它验证功能链路，不代表双方公平或策略强弱。

另一个 45 tick 受控片段以蓝床已毁和蓝方一人 4 HP 开始：tick 1 蓝方玩家最终淘汰，tick 16 开始与红床接触，tick 27 使用剪刀回收 1 羊毛。片段以外部时限截断，未产生自然胜负；对应输入、事实和每个边界均可从初始快照重放。示例脚本可重新生成记录及离线页面；本机还保存了从同一组帧渲染的四倍慢放视频（9.2 秒）。

四个预选样本均使用上述不对称预置，结果如下。每次恢复均比较该边界之后直到 episode 结束的每个 tick；同一 tick 从多个快照重复核对不能当作独立对局。

| 样本 | 结束边界 | 从起始边界验证 | 从 tick 200 验证 | 从 tick 400 验证 |
| --- | --- | --- | --- | --- |
| 101-A | tick 752，红队自然获胜 | 752 tick，226 条后续事实 | 552 tick，158 条事实 | 352 tick，88 条事实 |
| 102-B | tick 650，外部截断 | 未执行 | 450 tick，139 条事实 | 250 tick，69 条事实 |
| 103-C | tick 650，外部截断 | 未执行 | 450 tick，182 条事实 | 250 tick，112 条事实 |
| 104-D | tick 650，外部截断 | 未执行 | 450 tick，182 条事实 | 250 tick，112 条事实 |

这些验证固定代码、定义和 CPython 版本；四组不是 P9 的 40 局标准矩阵。应用内浏览器的安全策略拒绝加载本地 `file:` 页面，因此未完成真实浏览器中的视觉验收；已用离线脚本检查回放初始化、事件筛选和逐帧跳转，并检查生成视频画面。

2026-10-28 回放展示优化：界面新增队伍状态栏、地图缩放/跟随、关键事件标记及分页；播放器仍只读取既有记录。同代码哈希下的旧 P7 记录可重新导出新版 HTML，已导出的旧页面不会自动更新；后续 P8 和 P9 代码变更后，旧记录需使用其原版本重新验证，旧的自包含 HTML 仍可查看。界面逻辑可用 `node tests/viewer-smoke.cjs` 验证（Node.js 是可选的开发检查，核心运行不依赖它）。
