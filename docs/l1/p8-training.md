# L1 P8：共享参数 PPO 训练

用户于 2026-10-28 选择共享参数 PPO、固定脚本对手与本机 CPU 最小验收预算。实现采用 [PPO 论文](https://arxiv.org/abs/1707.06347)中的裁剪策略目标、线性共享演员/价值网络和 Adam；训练时可选安装 `numpy==2.3.5`，基础世界、脚本对局和回放不依赖 NumPy。此初版训练系统用于验证跨局学习与恢复，不承诺策略能在小预算内学会完整战术。

## 运行、评估与恢复

```bash
python -m pip install -e '.[training]'
# 用不对称 2v2 预置进行最小功能验收；输出目录必须不存在
bedwars-arena train-l1 --preset examples/l1-ppo-controlled-2v2.json \
  --seed 2026 --episode-limit 80 --episodes-per-update 2 --updates 1 \
  --eval-games 2 --output artifacts/ppo-first --json

# 新进程从完整检查点继续，配置、预置和对手版本沿用原记录
bedwars-arena train-l1 --resume artifacts/ppo-first/checkpoints/update-000001 \
  --episodes-per-update 2 --updates 1 --eval-games 2 \
  --output artifacts/ppo-resumed --json
```

若省略预置，训练使用标准新局；默认外部时限来自规则档案，可能很慢。可显式设置 `--episode-limit`、`--decision-interval` 和 `--opponent attack|defend`；恢复时若显式提供它们或 `--seed`/`--preset`，必须与检查点一致。`--eval-games` 必须为 0 或偶数：相同评估种子分别用于本轮开始时的冻结模型和训练后冻结模型，按局轮换训练队伍的两侧。评估不修改模型、优化器、训练计数或训练采样 RNG。

训练验收预置让两队各两名玩家在同一可行走区域近战，蓝床开局已毁、蓝方初始 4 HP、红方有一档防具；这是真实 L1 2v2 自然终局，但并非标准开局和公平对战。最小预算用于证明 PPO 数据、参数更新与恢复，不代表完整战术能力或可推广的胜率。对标准初始状态也应单独运行测试，报告任何外部截断。

## 观测与动作适配

所有模型输入仅来自隔离的公开观测；训练器不把未结算请求、内部队列或 RNG 传给策略。`l1-ppo-observation-v1` 把观测编码成 741 个 `float64` 值：

- 地图 4×8×16：将公开原始地面、玩家羊毛桥、墙和仍存在的床分别映射到与地图边界一致的 8×16 格子，按每格面积归一化并限制在 0–1。聚合是有损的；每个输入格子的归属规则固定且可追溯。
- 玩家 4×31：自身、队友、两名敌人依次排列，后两组内部按玩家 ID 稳定排序。字段包括身份/友方标识、三种生命状态、坐标、朝向、HP、防具、保护、背包、速度、击退、冷却、移动和交互类别/进度以及复活等待。未存活分支不伪造有效动作或装备。
- 地面物品 16×6：按到自身距离和实体 ID 排序，保留最近 16 项，包含存在标识、位置、铁/羊毛类别及数量；不足补零，超出上限的项目不输入模型。
- 全局 9：tick 相对于 Game End 的比例、自身固定席位 one-hot、双方床状态、地面实体数量及队伍侧标识。

`l1-ppo-discrete-v1` 有 49 个动作：保持；取消移动/交互；8 个移动方向；8 个转向方向；5 种手持选择；攻击最近可及敌人、破敌床、拆最近羊毛；8 个相邻桥面和 8 个相邻墙体放置方向；3 种购买；丢 1、至多 8 或全部铁。每次模型决策最多产生一个现有协议请求；持续通道在无更新时保持。掩码只排除缺少目标、资源或显然不满足位置等条件的请求，并不替代引擎的实时资格、朝向、遮挡、容量和竞争校验；其余被拒绝/失败的请求计入无效率。离散化仅约束此训练适配器，不改变世界原有的连续动作能力。

## 采样和更新

同队两个独立会话使用一份冻结参数版本；每局结束或截断之前不更新该版本。每个会话独立采样，但跨局模型和优化器由训练器共享。默认每次更新收集 2 个完整 episode，PPO 参数为：每 tick `γ=0.995`、`λ=0.95`、裁剪范围 `0.2`、学习率 `0.0003`、4 个 epoch、最大 minibatch 64、价值损失系数 `0.5`、熵系数 `0.001`、梯度范数上限 `0.5`。这些是本次实现的实验参数，并非 Hypixel 游戏参数。

仅队伍自然胜/负/平给 `+1/−1/0`；没有资源、击杀或破床过程奖励。等待复活不终止轨迹，永久淘汰后不采样虚构动作，但其最后一次决策仍可接收队伍最终奖励。 若策略异常、缺包或软超时触发 Runner 备用动作，则保留该席位终局奖励和故障记录，但丢弃该席位该局整条 PPO 轨迹，避免把备用动作冒充策略采样。决策间跨越 `d` 个 tick 时使用 `γ^d` 与 `λ^d`；自然终局不 bootstrap，只有外部截断时用最终公开观测的价值估计，两种标志同 tick 为真时按自然终局处理，见 [Gymnasium 的时限说明](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)。

`episodes/` 和 `evaluation/` 保存 P7 对局记录；`rollouts/update-*.npz` 保存公开编码、动作索引、mask、旧概率/价值、优势、目标、tick、玩家和对局 ID，可与输入记录按 `(match_id, player_id, tick)` 对照。`training-report.json` 记录配置、种子、固定对手版本、每局状态、无效请求、破床、最终击杀、铁拾取/花费和局长。胜率 Wilson 区间仅在独立试验假设下有统计意义；确定性重复局不构成独立随机证据。

## 检查点与边界

`checkpoints/initial-*` 和 `update-*` 保存参数、Adam 一阶/二阶矩与步数、更新/episode 计数、采样 PCG64 状态、规则/地图/场景哈希、预置哈希、动作/观测版本、对手版本、Python/NumPy/平台及 BLAS 环境。文件组在临时目录完成后发布，NPZ 加载禁用 pickle；文件哈希、形状、有限性、版本和预置均须通过后才恢复。种子和 PCG64 大整数以十六进制文本保存。当前只支持完成 episode 且 rollout 已更新的边界检查点，不声称从训练中的半局或未提交采样缓冲精确恢复。

一次对局新建世界和策略会话不会重建跨局模型或优化器；模型更新只在局间进行。由于世界记录严格绑定 Python 包内容哈希，P8 代码加入后旧 P7 快照无法用新代码直接恢复；旧的自包含 HTML 仍可查看，需新建对局生成当前版本的可重放记录。

## 本机最小验收（2026-10-28）

在 macOS arm64、CPython 3.12.14、NumPy 2.3.5 下，标准脚本对局的前 200 tick、启用完整 P7 记录和既有规则检查时，推进耗时约 7.78 秒（25.7 tick/s）；峰值 RSS 约 33.5 MB，完整记录约 1.37 MB。该测量是单世界短区间，推进时间不含结束后写出文件，不代表长局或 40 局平均吞吐。

随后以 seed 2026、受控 2v2 预置、每局上限 80 tick 收集两个 episode：分别在 tick 2 和 tick 11 自然结束，得到 26 条玩家决策样本；4 个 PPO minibatch 更新使模型哈希改变，Adam 步数为 4。新进程从检查点恢复时，参数、Adam 一阶/二阶矩与步数、PCG64 状态及 episode/update 计数均一致；再采两局（一次在 tick 80 截断、一次 tick 11 自然结束）并更新后，累计 4 局、2 次更新、Adam 步数 12。期间没有策略备用动作。

冻结评估使用两个种子并交换训练队伍侧；初始模型和首次更新模型各为 1 胜 1 负、0 平、0 截断、0 无效请求，名义 Wilson 95% 区间约 0.095–0.905。两局极少且预置不对称，不能据此认定策略强度或更新有效提高胜率。另以标准新局运行 200 tick 的 PPO 采样，得到 340 条决策和 324 条实际请求，外部截断、无备用动作；这只验证标准开局接口，零终局奖励时的参数变化不证明任务学习。

本机可检查的新版输出位于 `artifacts/l1-p8-training-v2/`、`artifacts/l1-p8-resume-v2/` 和 `artifacts/l1-p8-standard-smoke-v2/`；P8 基准测量保留在 `artifacts/l1-p8-benchmark-v2/`，它使用较早的代码哈希。P9 修正 CLI 状态文字后重新完成上述训练、恢复和标准开局烟测，以使新版检查点绑定当前代码；较早的 v1 输出仍保留，但不能在新版下直接恢复。按项目约定这些实验数据不提交 Git。P9 的标准 40 局矩阵须单独运行，不能用这些受控短局代替。

构建的 wheel 在仓库外的 Python 3.12 隔离环境中完成训练检查点加载与继续更新；该环境将本机已有的 NumPy 2.3.5 安装内容复制进去后安装项目 wheel，未验证从 PyPI 在线下载依赖。另在不含 NumPy 的 Python 3.11 环境验证基础 CLI 可用，训练入口明确提示安装可选依赖。
