## M0：工程初始化（已完成）

- Python 包布局、工程信息 CLI、开发安装及构建配置。
- 引擎、接口、策略、运行器、回放和前端目录。
- 架构、契约问题清单、开发指南和决策记录。
- 本地工程检查、GitHub CI、公开仓库。

M0 不包含游戏玩法、Agent 对局、网络服务或回放界面。

## M1：最小规则与本地闭环（基础模块进行中）

已落地 [TeamState 类型、参考规则与事件排序基础](decisions/0012-team-core-types-and-ordering.md)，有交易/冷却/恢复/排序行为测试。完整世界、物理/药效应用和双策略对局尚未完成；Q15 仍未核验，部分规则参数仅为显式启用的候选或实验覆盖。

按已接受的 [Python 进程内接入决策](decisions/0002-in-process-agent-interface.md)，先确定空间、规则、观测、动作和时间语义，再实现可用两个简单 Python 策略运行的无界面对局。验收应覆盖床/复活/淘汰与终局、非法动作、同动作序列的复现、隐藏信息边界。具体规则范围仍待确定。

物理正式采用平面加高度 B，前期允许先做严格俯视二维 A 实验，见 [0003](decisions/0003-grid-terrain-continuous-players.md)。实验的具体范围、A/B 兼容方式和竖直物理细节继续讨论；二维实验不能作为高度机制已完成或已验证的证据。

2026-10-26 补充：[物理与药效 P/F/V 设计](physics-effects-confirmation.md)现已整组采用，覆盖 A 范围、求解器/承载/击退、来源与周期/区域效果及新增阶段。已补[参数与证据目录](rules/physics-effects-parameters.md)，14 项未知和其他机制矩阵继续核验；物理/药效处理器与运行中的新阶段尚未实现，不能把数值资料整理视为 M1 完成。

接口实现同时验证观测/动作的可变数据隔离、消息值表示、同一决策轮统一推进和提交/执行动作记录；当前还没有这些实现或测试。

## M2：策略接入、训练与实验（实现待开展）

跨局持续学习是用户已确认的需求。[0015](decisions/0015-world-schedule-replay-failures-and-training.md) 已采用训练与世界状态分离、局内固定策略版本、跨局更新、基础结果奖励、被动席位和检查点恢复方向；训练算法、采样接口、更新批量与具体实现仍待落实，不能在每局初始化时隐式重置模型。具体阶段安排仍为建议。

在进程内契约稳定后，按接入需求增加独立进程适配，复用观测/动作语义而不复制引擎规则；具体通信协议、网络接入及标准环境适配仍待选择。增加与隔离方式相符的超时与异常行为、批量配置、种子集合和结果导出。先做正确性验证，再制定与测量吞吐量指标。

## M3：完整记录与回放（建议）

[0015](decisions/0015-world-schedule-replay-failures-and-training.md) 已采用快照边界、版本校验、输入记录与恢复原则；仍需落实完整记录格式与状态检查方法，再实现网页展示和时间轴。回放应能核对玩家、床、资源及可建造地形，而不只记录玩家位置。
