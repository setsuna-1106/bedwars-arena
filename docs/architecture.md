## 当前工程选择

- 使用 Python 3.11+、`src` 布局和 `pyproject.toml`，方便后续开发规则原型与外部策略适配。
- 使用 setuptools 构建 wheel/sdist；核心运行时暂不引入第三方依赖。
- 引擎、接口、策略、运行器和重放使用独立包；离线回放模板随 `replay` 发布，`web/` 保留说明。
- 首版策略接入已选择 Python 进程内调用，并保留独立进程适配的边界；该设计尚未实现，见 [0002](decisions/0002-in-process-agent-interface.md)。
- 空间表示已选择三维方块网格、玩家连续移动与轴对齐矩形平面碰撞体；方块边长为 1，水平 `(x, z)` 为矩形中心，向上为正的 `y` 为脚底高度，身体范围 `[y, y + H]`。正式采用平面加高度 B，前期严格俯视二维 A 实验限制单一行走层、无上下重叠通路。路径检查、表面接触合法、贴面滑动及 B 中落地/撞顶清零受阻竖直速度已接受，击退同样受障碍约束。连续运动量首期采用 binary64，时间为整数 tick，快照保证浮点往返恢复、显示截断不写回，禁止 NaN/无穷；首期验收固定版本/运行环境重放一致，跨平台逐位一致另验。地形底层存储/文件格式、水平轴正向/原点/地图范围与越界、数值容差、身体尺寸及碰撞求解细节待定，见 [0003](decisions/0003-grid-terrain-continuous-players.md)。尚无相应物理实现。
- 玩家之间可互相穿过，队友与敌人的身体占位均不阻挡或推挤，玩家仍与方块碰撞；其他玩家占据出生位置不妨碍复活。攻击命中与伤害/击退分别按相应规则处理，重叠目标选择等细则待设计，见 0003，尚无相应实现。
- 攻击已选择受玩家朝向限制，转向采用瞬时更新、不单独耗时；移动与朝向独立，允许侧移和后退，静止时保留朝向。允许角度、同轮结算顺序及具体机制待设计，见同一空间决策。尚无相应实现。
- 击退已选择通过速度变化产生持续运动并逐渐衰减；受击期间可移动，反向输入可少量削弱但不能使击退停止或反转，击退仍占主导。速度状态表示、受限控制与合成、衰减细节待设计，见同一空间决策。尚无相应实现。
- 主动移动已选择即时响应，不模拟主动加减速；主动速度由当前动作与规则计算，击退所需速度信息持续保存，停止主动移动不清空击退。正常未更新继续执行见 0009；具体字段与中断细则待设计。尚无相应实现。
- 死亡清空携带的铁、金、钻石和绿宝石，存活击杀者按容量接收；击杀者同批死亡则对应资源直接销毁、不掉落但保留击杀统计。无有效击杀者按死者死亡当刻位置安全就地掉落，否则销毁，不回退。先固定本批所有死者转移前资源，再统一清空并分别结算，避免循环转移。安全依有效地图范围、承载与非虚空判断，与敌人或队伍无关。精确几何/具体事件编码仍待设计，批次提交原则已接受，见 [0004](decisions/0004-death-resources-and-statistics.md)。尚无相应实现。
- 击杀归属已选择直接致死归攻击来源、窗口内环境死亡归最近有效敌方攻击者；当前生命保存最近攻击者与仿真时刻，复活清空。窗口与有效攻击等细则待设计，见同一死亡结算决策。尚无相应实现。
- 本局统计已选择 `kills`、`deaths`、`final_kills`、`final_deaths` 四项，分别记录普通和最终击杀/死亡；同一次事件只进入一类，四项跨复活保留，总数与比值派生。尚无相应实现。
- `inventory` 与本局跨死亡的 `progression` 分开：一般消耗品清除，防具和剪刀购买记录保留，已购镐/斧降一级且最低基础级保留；团队升级归 `TeamState`。背包采用物品数量表和等效堆叠容量约束，四种资源同表记录，不维护独立钱包，容量占用由数量派生。见 [0005](decisions/0005-inventory-and-progression.md)。容量数值、其他接收顺序与具体装备字段待设计，尚无相应实现。
- `progression` 基础字段已定 `armor_tier` / `shears_unlocked` / `pickaxe_tier` / `axe_tier`；工具等级表示当前可恢复等级、未购为空，死亡按规则降级，不使用历史最高档。具体类型、档位编码与规则映射待设计，见 0005，尚无相应实现。
- 穿着防具由 `armor_tier`、规则表和团队升级按部位派生，不保存独立可变装备表，不进入普通背包或占用容量；首版不支持独立脱装/换装及防具耐久。购买升级与复活后查询均依据当前源状态，具体部位属性、减伤计算和观测另定，见 0005，尚无相应实现。
- `AliveState` 显式保存 `held_item`，引用背包物品键或为空，不复制数量/属性或增加容量占用。合法切换瞬时完成、不占持续通道，同物品选择不变；切走中断需持续持物的交互、丢弃未完进度且不提前扣物，移动继续、冷却不重置。耗尽/移出时清空，无效切换保留原手持/交互，购买/拾取不自动切换；开局/复活生成装备后按配置手持木剑。最后一件物品成功使用的结果不因归零清手而撤销。具体同刻时序、类型及其余初始装备仍待设计，观测可见性另定，见 0005，尚无相应实现。
- 满容量时购买整次失败且不扣费，拾取部分接收并原地保留余量；击杀资源的接收溢出在击杀者当前位置安全时掉落，不安全则销毁余量。购买容量按完整扣费/发货后的结果检查。尚无相应实现。
- `vitality` 分别保存普通生命与剩余吸收生命；最大生命由规则和效果计算。普通可吸收伤害先扣吸收，普通生命耗尽触发死亡；复活普通生命回满、吸收清零。见 [0006](decisions/0006-vitality-and-absorption.md)。数值、伤害/效果细则与时序待设计，尚无相应实现。
- 本生命临时效果死亡时统一清空，旧效果的后续事件不能影响新生命；团队升级保留在 `TeamState`，复活后重新计算其作用。同种药水再次饮用使用新等级和从当前仿真时刻计算的新时长，不累加旧时间。不同来源的等级型增益分别计时、只取最高等级，弱效果不暂停计时且未到期时可恢复。见 [0007](decisions/0007-temporary-effects.md)。基础 `EffectState` 已确定实例 ID、种类、来源、等级、到期及下一触发时刻六字段；具体类型、特殊效果合并与周期触发细则待设计，尚无相应实现。
- 周期效果首次施加后等待一个完整周期再触发；同等级、同周期刷新时，新记录承接原下一次触发时刻，只按规则重算到期时刻；旧记录被替换，不产生重复或额外立即触发。等级/周期变化及多来源周期触发待设计，尚无相应实现。
- 主动冷却在 `PlayerState` 公共外层的 `cooldowns` 中按组记录可用时刻；各组规则指定死亡清除或保留，保留原截止时刻且等待复活期间继续计时、复活不重置。保护状态复用 `effects`，不重复保存保护倒计时，行为与等级型增益合并规则分别设计。见 [0008](decisions/0008-cooldowns-and-protection-effects.md)。各组处理选择、具体机制、时长与共享分组仍待核对，尚无相应实现。
- 动作采用 `movement` / `interaction` 双通道，移动可与一项交互并行，交互通道一次一项；正常未更新保持原动作及进度，相同持续动作不重启，不同合法新动作替换指定通道、丢弃未完进度，无效指令不取消旧动作，不自动排队。一次性结算不重做、已完成结算不撤销。见 [0009](decisions/0009-movement-and-interaction-channels.md)。基础 `ActionState` 七字段、W08 取消/去重及 0015 异常备用动作已定；具体类型、其他中断与耗时等细则待设计，尚无相应实现。
- 饮药/进食完成、方块成功放置、投掷/发射消耗品实体成功生成时分别扣物；主动取消/失败不提前扣除，已生成状态不回滚。死亡清理与主动中断分别处理；运行进度与开始时刻由引擎管理，尚无相应实现。
- 死亡立即终止并清空双通道、丢弃未完进度，复活后等待新指令，不自动恢复旧动作；记录死亡这一结束原因，旧动作实例/完成事件不能作用于新生命。已放置方块、已发射实体仍按自身规则处理，本生命临时效果按 0007 清理，冷却按 0008 的组规则处理。各组处理选择、出生保护边界和同一时刻顺序待设计，见 0009，尚无相应实现。
- 目标消失、目标玩家当前生命结束或执行中不满足动作要求的距离/朝向时，中断对应动作并丢弃未完进度；暂时失效也不暂停保留，恢复后需重新下令。正常冷却等待单独处理，其他通道按自身条件执行；检查时序、精确边界和未列中断仍待设计，见 0009，尚无相应实现。
- `PlayerState.life` 已选择 `AliveState` / `RespawningState` / `EliminatedState` 三种互斥分支；身份、队伍、本局统计、购买进度与冷却保留在外层，当前生命的位置、生命值、背包、临时效果与动作归存活分支。等待复活和淘汰状态不保留仍有效的旧存活动作，复活构造新的存活分支。见 [0010](decisions/0010-player-lifecycle-branches.md)，完整字段及转换细节待设计，尚无相应实现。
- 公共外层的 `life_index` 首次出生为 1，每次成功复活加 1，死亡/等待/淘汰不递增；本生命动作/效果延迟事件执行前校验存活分支、玩家/生命序号及实例有效性。已发射世界实体独立运行，不因来源生命结束自动销毁；快照保留生命序号。具体类型/编码与事件调度仍待设计，见 0010，尚无相应实现。
- 死亡后的 `RespawningState` 基础字段已定为 `died_at` / `respawn_at`，记录死亡与计划复活的仿真时刻；剩余等待派生，不维护独立倒计时。成功构造新生命才递增序号；生命周期调度与本生命动作/效果事件分别校验。时间类型、特殊流程资格及等待时长仍待设计，见 0010，尚无相应实现。
- 普通死亡结算时床仍在则进入等待复活、床已毁则淘汰；等待中丢床不取消已获准的本次复活或重置等待，复活后下一次无床死亡才淘汰。等待分支即表示本次已获准，不再单独维护 `can_respawn`。同一时刻破床/死亡顺序仍待定，见 0010，尚无相应实现。
- `EliminatedState` 基础字段已定 `eliminated_at` / `reason`，记录淘汰仿真时刻和原因类别；当前类别为 `final_death`，死亡方式/击杀者/位置仍归死亡事件。外层统计、购买进度与刚结束的生命序号保留；具体类型/编码和其他类别待设计，见 0010，尚无相应实现。
- 首版每张地图为每队配置一个固定出生点及初始朝向，同队成员开局/复活共用；复活位置表示矩形中心，朝向取该配置，击退速度清零，玩家占位不阻挡。地图划定覆盖完整出生矩形的禁建区域，对所有队伍禁止放置方块，并保护出生承载地形不被拆除或爆炸破坏；玩家伤害/击退仍按各自规则处理。具体保护范围/边界及地图格式仍待设计，见 0010，尚无相应实现。

- `TeamState` 的五字段、只读值表示、JSON 编码/恢复、纯交易与状态转换已实现，见 [0012](decisions/0012-team-core-types-and-ordering.md)，设计依据仍为 [0011](decisions/0011-team-state.md)。完整玩家/世界引擎未实现，内部资格输入必须由后续 core 规则处理器计算。
- 团队升级与陷阱交易返回新的状态、扣款后库存和事件，调用方作为同次世界更新提交。陷阱只追加、可重复、按队首消费且必须明确预算；未实现主动移除。触发结果为效果/报警意图，尚未直接改变玩家效果。
- 内置档案按模式区分升级价格，社区候选价默认禁止使用；官方历史队列 1/2/4 钻石与三档容量及已查到的效果时长作为参考。共享冷却仍需显式实验/核验覆盖，Q15 未关闭。

## 目标边界

以下描述指导后续实现，目前没有相应运行链路。

用户已确定以 Hypixel Bed Wars 为现实规则参照；日常规则入口为[规则参考](rules/hypixel-bedwars.md)，证据背景保留在[规则调研](../reports/2026-10-25-hypixel-bedwars-rules.md)。模式、地图、规则快照与二维化简化仍待确定。

1. `core` 管理真实世界状态；不能依赖策略、网络或渲染。
2. `interfaces` 从状态派生每个参赛者能获得的观测，校验动作格式；规则合法性归 `core`。
3. `agents` 首版在进程内消费独立观测并返回动作数据；不能持有引擎或世界状态引用。未来进程适配器复用同一数据语义。
4. `runner` 收集同一轮动作，按明确契约推进一次世界，处理对局生命周期和实验记录。
5. `replay` 记录规则、地图、种子、策略版本、行动及状态；回放前端读取记录。
6. `web` 展示状态与事件；游戏规则不在前端再实现一份。

完整状态仅用于引擎、受控实验和回放；参赛者观测、info、错误消息及合法动作提示都需遵循同一信息边界。

## 已确定的策略接入边界（待实现）

- Runner 组织同一决策轮，从同一世界状态准备观测、调用策略并收集动作，再统一调用引擎推进。
- 观测不与引擎或其他玩家共享可变引用，包括嵌套内容；动作校验与接收后由引擎持有独立数据。
- 观测和动作采用可显式转换为 JSON 兼容值的数据契约；进程内不要求每轮实际编解码。具体类型和字段待设计。
- 记录关联对局、策略、决策轮、仿真时刻及提交/实际执行动作；决策轮与 tick 不预设一一对应。
- 首版没有进程隔离，不承诺强制终止卡死策略；异常/软超时/必需包缺失的备用取消已按 0015 采用，真正硬超时留待独立进程，尚未实现。

详见 [0002](decisions/0002-in-process-agent-interface.md)。本次选择不增加网络服务或通信依赖。

## 已确认的训练需求（待实现）

用户明确平台用于决策模型训练，需要支持跨局持续学习。每局游戏世界的初始化与学习状态的初始化必须分开；开始新对局不得自动重新初始化既有模型参数、优化器状态或训练进度（若所选算法使用这些状态）。经验数据和缓冲区如何保留，由学习算法及实验配置定义。

跨局学习状态与本局目标、历史观测、循环模型隐藏状态等会话数据分别管理；会话按局创建，复活不重置，永久淘汰后转为无行动被动席位直至整局结束。初始化、采样反馈、模型更新和训练恢复接口待实现，不能从“每局创建策略会话”推导出“每局重新训练模型”。

局内模型版本固定、训练器跨局更新、基础结果奖励及检查点原则已按 0015 采用；P8 现已实现共享参数 PPO、可选 NumPy 依赖与局间检查点，具体编码、预算和范围见 [P8](l1/p8-training.md)。

## 尚未确定

地形文件格式、水平轴正向/原点/边界与碰撞细节、A/B 接口兼容、未列玩法与必要参数、局部视野和隐身的具体几何、完整消息契约、未来进程/网络协议及性能目标仍待落实。三维网格、A 单层限制、坐标/方块单位、冲突结算主要原则及 0015 的终局/截断和策略生命周期方向已确定；平台 20 Hz 时间与排序基础已经实现，`WorldState` / `PlayerState` 的完整字段与类型仍待设计。
