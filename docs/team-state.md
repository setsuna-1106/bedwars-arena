# TeamState 已确认设计总览

更新：2026-10-26。

状态：逻辑设计已收尾，五字段类型/JSON 编码、参考规则档案、纯状态转换与事件排序基础已按用户要求实现，见 [0012](decisions/0012-team-core-types-and-ordering.md)。完整世界引擎、空间/牛奶资格与实际效果应用仍未实现，Hypixel Q15 未核验完成。设计依据见 [0011](decisions/0011-team-state.md)。

## 已确认的状态结构

| 字段 | 内容与归属 |
| --- | --- |
| `team_id` | 队伍标识；成员从 `PlayerState.team_id` 派生 |
| `bed_state` | `status` 与 `destroyed_at`；几何/所属队伍归地图，拆除进度归玩家交互，摧毁来源与原因归事件 |
| `upgrades` | 已购买的升级 ID 到当前等级的映射，未购项目不保存；未知 ID 属于错误 |
| `trap_queue` | 有序的待触发陷阱实例列表 |
| `trap_ready_at` | 队伍共享的下一次陷阱触发可用仿真时刻；整组冷却机制待与 Hypixel 核验（Q15） |

陷阱实例基础字段为 `trap_id`、`trap_type`、`purchased_by`、`purchased_at`；已实现字符串 ID/枚举与整数 tick 编码，见 [v1 Schema](../schemas/team-state-v1.schema.json)。队员名单、出生配置、升级属性与其他派生数据不在队伍状态中再维护独立真值。

## 已确认的主要行为

- 床被摧毁时状态/时刻/事件一次结算，重复处理不重复破床；等待复活者已取得的本次资格不因丢床撤销。
- 升级请求指定目标等级，每次一级；结算重查资格/当前等级/资源，扣购买者背包、更新等级与事件一次完成。同队并发请求相同目标等级，按统一顺序至多一笔成功，后续不自动购买更高等级。
- 陷阱购买只能追加到队尾，不允许玩家主动删除、替换或重排；同种可重复购买，以不同实例占据多个位置，不合并。
- 每笔陷阱购买都须满足资格、资源、费用上限与容量约束。`max_cost` 必须提交；按结算实际价格成交，超上限失败，降价按实际价扣费。
- 只检查队首，一次有效触发只消耗一个实例，出队/结果/事件完整结算；条件不满足不消耗或跳过。已施加的玩家临时效果归其 `effects`。
- 成功触发时一并将 `trap_ready_at` 更新为当前时刻加规则冷却时长；购买/空队列/玩家死亡/丢床不重置。时长未定，不以未知为零。
- 丢床后队列保留、继续按序触发，满足条件仍可购买；触发区域使用地图配置的基地范围，不依赖床对象存在。

上述共享冷却的作用范围、计时起点/时长和重置边界仍需按 [Q15](rules/hypixel-bedwars.md) 与 Hypixel 对照。项目已采用与现实已验证分别记录。

## 已确认的队伍生命周期

首版单局内固定阵容；本局启用的每支队伍至少有一名玩家，地图预留但未启用的队伍不创建 `TeamState`。中途加入/换队作为后续扩展。

队伍参赛状态由成员的生命分支派生：

| 条件 | 派生结果 |
| --- | --- |
| 至少一名成员处于 `AliveState` 或 `RespawningState` | 队伍仍在参赛 |
| 所有成员均处于 `EliminatedState` | 队伍淘汰 |

- 床的存续不单独决定淘汰；全队等待复活仍在参赛。
- 不新增独立可变的 `is_eliminated` 或成员计数，仍保留当前五字段。
- 从参赛转为淘汰时记录一次队伍淘汰事件。保留队伍记录及原床状态、升级、陷阱队列与截止时刻，用于快照、回放与检查；不改写为暂停的剩余冷却。
- 淘汰队伍停止陷阱触发，也不能再购买。保留队列不表示队列仍有游戏作用。
- 已经施加的玩家效果、已经生成的世界实体继续遵守各自规则，团队淘汰处理不额外删除它们。

最终胜负与同时全灭的结果归 `WorldState`/终局规则另定，本节只确定队伍参赛状态。

## 已确认的陷阱触发条件（待 Hypixel 核验）

采用“检查当前是否存在合格入侵者”，不要求每次触发前重新跨越基地边界：

1. 队伍仍在参赛，队列非空，且当前时刻已达到 `trap_ready_at`。
2. 在该队地图基地范围内，存在存活敌方玩家，并通过队首陷阱的规则资格检查。
3. 多人同时符合条件时，按开局配置中固定的玩家顺序选一名触发者，确保相同配置和状态得到相同选择。
4. 该次检查只触发一个队首实例，结算后不连锁检查剩余队列。

这样，敌人持续停留时，冷却到期后仍可在后续检查中再次触发；敌人已在基地内时新购陷阱，也在下一次满足条件的检查中参与触发。触发者与效果接收者分别处理，具体陷阱仍可按规则作用于入侵者、防守队友或产生报警。

不新增上一轮入侵者集合或进入/离开历史字段。牛奶是否阻止触发、是否消耗陷阱、是否只免疫部分效果仍待核验；当前纯函数接收 core 计算的合格候选，不允许策略自行声明资格。排序基础已按 0012 落地，具体几何、检查频率与完整世界处理器仍未实现。

这组触发方案已采用，继续保留 Q15 的 Hypixel 待核验状态；不表示线上规则已经确认。

## 已确认的标准开局初始化

令 `t0` 为本局初始仿真时刻，标准开局使用：

| 字段 | 初始值 |
| --- | --- |
| `team_id` | 本局配置的对应队伍标识 |
| `bed_state.status` | 床存在，编码为 `present` |
| `bed_state.destroyed_at` | 空，编码为 JSON `null` |
| `upgrades` | 空映射 |
| `trap_queue` | 空列表 |
| `trap_ready_at` | `t0`，表示初始没有尚未结束的触发冷却 |

- 初始化校验队伍/玩家关联以及地图中的床、出生配置与基地范围引用；不把地图空槽位当作参赛队伍。
- 启动完整对局前必须具备所启用规则需要的容量、计价、冷却时长等配置；缺失值不能被当成零、关闭或无限。
- 以上只定义标准新局。恢复已有快照时保留原五字段、队列顺序/实例 ID 与原截止时刻，不重走新局默认值。
- 预置升级、预置陷阱或无床训练场景的初始化覆盖接口另行设计；不把标准新局默认值解释为禁止未来场景训练。
- 世界初始化继续与模型、优化器及跨局训练状态分离。
