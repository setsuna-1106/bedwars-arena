日期：2026-10-27。**状态：P0 已完成静态定义与规格；P1 已完成状态、提交、调度和基础快照；P2 已完成二维几何与运动；P3 已完成动作接收、控制与观测基础；P4 已完成经济和拆建；P5 已完成战斗、死亡复活与终局；P6 已完成 Runner 与首场脚本对局；P7–P9 尚未执行。L1 规则及参数 v0.1 已由用户采用，完整 L1 与对局引擎尚未实现。**

依据：[0016 范围](decisions/0016-four-level-platform-and-l1.md)、[已采用实验参数](rules/l1-experiment-parameters-v0.1.md)、0013–0015 与 P01–P10 的适用规则。用户本轮要求“采用，并给出 L1 的完整的实现规划”；后续按用户要求分阶段实现和验证；P0 不启动整个引擎。

## 1. 目标与边界

L1 最终交付必须能：

1. 从固定三岛地图和显式实验档案创建完整二维 2v2 对局。
2. 四名独立策略收集资源、购物、持物/拆建、用剪刀回收羊毛、近战/击退/破床、复活/淘汰并得到唯一结果。
3. 无界面批量运行，记录版本、种子、输入、事实和快照，恢复后不重复执行。
4. 用二维回放查看地形、玩家、资源、床和动作，可暂停及逐 tick 检查。
5. 用一个明确选定的训练算法完成跨局采样、更新、冻结评估、保存/恢复与继续训练。

不以实现 L2–L4 的陷阱、团队升级、容器、分享、药水、投射物、三维运动和 Hypixel 现服校准作为 L1 前提。现有通用设计保留，但关闭的机制不建立空壳运行处理器。世界接口预留扩展边界，不同时开发四套引擎，也不预先抽象所有高级玩法。

### P1：完整状态、原子提交与调度基础（已完成）

**依赖：** P0。

**实现：**

- `PlayerState` 三生命分支、背包/进度/手持、冷却/保护、双动作通道及 life_index；`WorldDefinition`、`WorldState` 与恢复必需 execution 字段。
- 世界构造器：标准局和训练预置共用校验，初始 tick=0、默认装备/保护/生成器/赛程任务，ID 统一分配；精确恢复不重置。
- `ChangeSet`/提交计划：处理器只读当前状态并返回计划，引擎检查后一起提交状态、任务、ID 进度/去重/游标，再输出事实。
- 消息分为 ScheduledTask、Intent、FactEvent，不能直接给旧 ScheduledEvent 换名字而忽略语义；取消、失效原因和整局去重随 execution 保存。
- 阶段游标独立于队列最后一次 pop；空阶段也推进游标。任务消费和新任务入队与状态一起成功提交。
- 新完整世界快照与基础编码：binary64 有限值往返、定义哈希/引用/版本校验、独立随机流、日志游标与不可变对外边界。
- 失败标记为世界推进故障，不发布半个 tick，不生成假结果；后续只能显式从完整边界快照恢复，不承诺整 tick 自动回滚。

**产物位置建议：** `core/player.py`、`core/world.py`、`core/execution.py`、`core/transactions.py`、`core/messages.py`、`replay/snapshot.py`。

**完成标准：** 新局/合法预置/边界快照往返；故意让批次校验失败，状态/队列/ID/游标均不出现半提交；空队列阶段、过期任务、同 ID 重试/冲突与恢复后去重正确。

**迁移约束：** 不让世界加载器把队列 schema 1 自动视作完整世界。保留现有 TeamState/旧队列接口和测试；新调度格式显式版本化。若不能从旧数据唯一恢复阶段、取消和因果等新信息，明确拒绝升级该旧快照，不补造历史。

### P2：二维几何、承载、碰撞与运动（已完成）

**依赖：** P1。

**实现：**

- 稀疏方块网格、床特殊碰撞对象、桥面/墙体目标层；负坐标 floor、半开格归属和接触合法分别处理。
- 统一距离/射线遮挡/承载/安全掉落查询，供战斗、拆建、拾取和商店复用，避免各模块算出不同几何。
- AABB 扫掠碰撞、最早接触/贴面滑动、同时接触、8 次迭代上限与诊断。
- 连续主动移动、P07 击退合成/衰减/碰撞消除；没有跳跃、竖直速度或身体互相阻挡。
- 路径首次失去承载产生死亡候选，不能跨空隙或在后阶段补桥自救；P5 接入统一死亡提交前，P2 场景只验证候选而不伪造完整死亡系统。

**产物位置建议：** `core/geometry.py`、`core/terrain.py`、`core/physics.py`，运动/几何边界测试。

**完成标准：** 直行/斜行等速、撞墙不穿透、贴边滑动、角点/负坐标、一步跨空隙仍坠落、击退不能被反向输入完全抵消、墙碰撞与承载丢失正确。

### P3：动作接收、控制与观测（已完成）

**依赖：** P1/P2。

**实现：**

- 每轮每玩家一包，绑定对局/玩家/轮次/observed_tick/life_index；外部 ID 与内部 action_id 分离。
- W08 的分层校验、同 ID 比较、接收 accepted 与执行 applied/failed 分离、通道/瞬时组冲突、输入封口/迟到拒绝及旧轮重试查询。
- 20 阶段按转向→切手→移动→交互更新；正常省略保持，异常备用取消，切手/目标失效/死亡等中断明确。
- 动作持续与一次性语义，开始/完成/中断关联 ID；资源丢弃使用已采用独立瞬时组。
- 控制阶段计算攻击/破床启动资格以解除保护；后阶段仍复核，不把“启动成功”当保证伤害/破床成功。
- 全局观测只从完整边界复制：公开已采用字段，不包含待执行请求/内部队列/RNG 等；反馈和动作掩码也遵守同一边界。

**产物位置建议：** `interfaces/actions.py`、`interfaces/observations.py`、`interfaces/feedback.py`、`interfaces/policy.py`、`core/controls.py`。

**完成标准：** 改写观测不能改变引擎；四席位同边界；收集顺序不改变结果；一次购买/放置/丢弃不被 k>1 重发；重试不重复结算，旧生命请求不进入新生命。

### P4：经济、商品、拆建与回收（已完成）

**依赖：** P1–P3。

**实现：**

- 背包数量与等效堆叠容量、商品报价、升级剑替换/手持清空、防具进度；个人铁商店独立于旧团队钻石购买。
- 25 阶段基地/中央生成，32 阶段按固定玩家/实体顺序拾取；满额续期、部分产出/接收、延迟/寿命和安全位置检查。
- 40 阶段购物，45 阶段丢资源及放置完成，50 阶段拆羊毛/玩家破床；普通方块实例 ID 随替换更新。
- 工具回收：剪刀正确对应、固定耗时、直接入包/溢出掉落/不安全销毁与方块移除一起提交；床和原始岛屿不生成材料。
- 拆墙下桥面需先清墙，禁建区/重叠/支撑/遮挡/朝向复核；拆掉承载后的玩家与地面实体检查。
- 地形/实体变更使相关几何与积累查询缓存失效；移除旧方块不让其他拆块者继承到新实例。

**完成标准：** 脚本输入可完成“拿铁→买羊毛→搭桥→换剪刀→回收”；同格争抢只成功一次且不重复扣/返；满包购买全败/拾取部分成功，满包回收按规则落地；可同 tick 拾取后买物，不能同 tick 先切到之后才买到的物品。

### P5：战斗、死亡批次、复活与终局（已完成）

**依赖：** P1–P4。

**实现：**

- 持续单目标近战、目标生命绑定、几何/朝向/遮挡、攻击/受击冷却、保护/减伤、击退与有效伤害归因。
- 60 阶段固定攻击资格、逐笔处理规则、统一死亡；互杀保留资格，虚空已失效者不能继续攻击。
- 同批资源先冻结再转移，禁止循环转移；击杀者本批死亡则资源销毁；无有效击杀者按死亡位置安全性掉落。
- 复活资格在死亡时固定，60 tick 后构造新生命/装备，life_index 递增；保持防具进度，清旧动作/效果/归因与指定冷却。
- 70 阶段从玩家生命派生队伍淘汰；90 阶段唯一结果。8 分钟全局毁床、10 分钟 Game End 依既定顺序处理。
- 终局奖励在 Runner/训练层根据世界结果计算，统计与世界结果不能反向从日志或奖励推导。

**完成标准：** 有床死亡/无床死亡、等待中失床、同 tick 破床后死亡、互杀/资源守恒、两队同时淘汰、双方都等待复活、定时毁床不记玩家破床、Game End 比较/并列均通过。

### P6：Runner 与第一场完整 2v2（已完成）

**依赖：** P1–P5。

**实现：**

- Runner 绑定四席位策略，创建/关闭每局会话，按共同观测收集并封口动作，始终逐 tick 推进；k>1 提前自然终局立即停止。
- 异常/缺包/软超时记录备用双通道取消；墙钟不改变仿真 tick，软超时不承诺能杀死卡住的 Python 回调。
- 每席位按生命分支请求动作；等待复活保留会话，淘汰保留被动席位直到整局结束，奖励回到固定阵容。
- `EconomicAttacker` 和 `DefensiveCounterattacker` 两种确定性脚本策略：自行导航、购买/切手、搭桥和战斗；仅使用正式观测/请求，不读 WorldState 或写地形作弊。
- 运行清单记录代码/环境/profile/map/模型版本、固定席位、seed、实际输入及所有备用决策；CLI 支持单局与批量报告。
- 正确处理 episode 外部截断以及同 tick terminated/truncated，冻结模型版本，不在一局中自动换训练权重。

**完成标准（G1）：** 一条正式 CLI 路径从配置创建四席位对局并结束，生成完整运行清单/事件/快照/结果；有控制场景实际发生搭桥、购物、破床及最终淘汰，不能仅靠等待 10 分钟平局视为完整玩法验收。

### P7：完整日志重放与二维回放

**依赖：** P6；基础快照/输入日志已从 P1/P3/P6 接入。

**实现：**

- 输入日志作为重放来源，实际动作只用于核对，不重复投递；恢复已封口请求、队列游标、见过的 ID、取消标记、RNG/ID 和 Runner 时限基准。
- 初始/终局/每 200 tick 快照与索引；逐 tick canonical 世界状态/事实比较，报告第一次偏差及对象路径。
- 简易网页采用 HTML/Canvas 加少量 JavaScript，不引入另一个规则引擎；通过本地读取记录或文件选择器查看，不要求服务器部署。
- 同屏显示地形层、床、玩家/朝向/HP/保护、资源与动作；检查背包/冷却；暂停、拖动时间轴、逐 tick、变速播放。
- 只消费已记录状态与事实，画面插值不写回物理；暂停界面不改变引擎规则。

**完成标准（G2）：** 4 局分别从早期/中期恢复后，完整逐 tick 状态与事件一致；界面可定位一次回收、一次失床死亡和一次碰撞。故障恢复从最后完整边界开始，不把中间缓存当合法快照。

### P8：最小训练闭环

**依赖：** G1、经 P7 验证的数据与恢复链路。训练算法选择是本阶段入口工作，不阻塞 P0–P7。

**入口方案需要确定：**

| 项目 | 需要输出的具体方案 |
| --- | --- |
| 算法/依赖 | 选定一个可实现的初版算法及固定依赖版本；建议优先评估共享参数的独立玩家 PPO，但目前没有采用 PPO 或任何库，不同时实现多个算法 |
| 观测编码 | 固定地图张量与玩家/资源/动作字段，归一化、玩家/队伍标识、变长实体的编码和上限；与原始观测一一追踪 |
| 动作编码 | 明确移动/转向、交互类别、目标、手持、购买、丢弃数量的模型输出；若离散化，记录为训练适配，不修改连续世界动作能力 |
| 采样语义 | 持续动作和无更新表示、invalid request、等待复活/淘汰、决策间隔、自然终局/截断的 mask、discount 和 bootstrap 规则 |
| 模型/预算 | 网络结构、设备、batch/rollout 大小、更新次数或环境步预算、随机种子、保存频率；先测实际吞吐，再设置现实资源预算 |
| 对手与评估 | 初期先固定脚本对手，评估冻结并交换席位；是否随后增加冻结历史模型池另记录，不把即时更新对手混入同一局 |

**实现：**

- 新建独立 `training/` 包和可选依赖 extra，安装/运行无界面世界不要求训练库或图形库。
- 完整采样→轨迹整理→训练更新→新局绑定新权重版本→冻结评估；不在每次 reset 重建优化器。
- 等待复活不作为智能体死亡终止训练轨迹；淘汰席位无动作，但保留最终队伍奖励。模型会话与跨局参数分开保存。
- 检查点保存模型、优化器、更新计数、采样/对手版本及 RNG；若算法依赖缓冲区/回合中状态，显式保存或只在一致边界保存。
- 始终只用已采用的团队终局奖励，不为获得学习曲线私自加资源/破床/击杀塑形。
- 对照固定脚本/未训练策略报告胜负平、无效请求率、破床/最终击杀、资源利用和局长，并报告置信范围/样本数；功能完成不要求胜率提升。

**完成标准（G3）：** 在完整 L1 上跨越多个 episode 完成至少一次有效参数更新；重置世界不清学习状态；保存后恢复可继续采样/更新，模型和优化器/计数保持一致；冻结评估期间权重不变。可用训练预置做故障排查，但只在单队小任务上更新不算完成 L1 2v2 训练验收。

**已知风险：** 全局观测不消除稀疏奖励和多动作组合难度。初版训练验收证明训练系统运行正确，不承诺在某个预算内学会全套战术；改课程/奖励/对手安排必须记录成新实验选择。

### P9：端到端验收与交付

**依赖：** G1–G3。

**实现/验收：**

- 执行已采用的 40 局矩阵：两种脚本、10 seeds、两队分配与队内席位组合 4 种，记录明确运行列表；不把相同确定性局重复计为独立随机证据。
- 至少 4 局做早/中快照恢复核对，包含已封口待处理请求、复活等待、持续拆建/攻击、满包回收和终局附近的边界场景。
- 注入策略失败、错误数据、无效任务、容量超限和提交故障，核对停止/备用动作/无半 tick 发布；检查世界、多个 episode 与学习状态互不串用。
- `scripts/check.py`、对应行为/集成测试；构建 sdist/wheel，从仓库外新环境安装并加载 L1 配置/地图，运行 CLI 和小对局。训练依赖用独立环境验证。
- 测量单世界/批量 tick/s、每局墙钟、内存和日志体积，记录设备/版本和记录级别。先串行正确性，再决定是否有必要引入多进程采样；不改变固定排序或减少规则检查掩盖性能问题。
- 更新 README、架构、CLI info、示例、规则版本、运行/训练/恢复/回放教程与限制；交付一份可检查的样例完整记录和训练检查点说明。

**完成标准（G4）：** 下节验收矩阵全部有结果，必需场景通过；已实现状态与文档一致，任何跳过/限制明确列出。不把提交、推送、发布仓库或部署网页作为本规划已经执行的动作。

## 5. 固定阶段与 L1 处理器映射

| 阶段 | L1 工作 |
| --- | --- |
| 0 | 保护/受击保护等到期、地面物品到期；生成器升级关闭 |
| 10 | 已获资格的玩家复活，构造装备/保护/新 life_index |
| 20 | 转向、切手、移动/交互更新、取消、启动资格与主动解除保护 |
| 25 | 资源生成，满额检查及续期 |
| 30 | 主动移动/击退/碰撞/承载失效 |
| 32 | 普通地面拾取，分享关闭 |
| 35 | 无 L1 区域效果处理器；阶段仍按调度契约走过 |
| 40 | 个人商品购买与背包/进度/手持原子更新 |
| 45 | 放置完成、主动丢弃，随后必要空间/承载复核 |
| 50 | 拆羊毛/回收、玩家破床，再全局毁床；地形变更复核 |
| 55 | 无 L1 周期治疗处理器；阶段仍走过 |
| 60 | 合格攻击、伤害/击退/归因、虚空与统一死亡批次 |
| 70 | 队伍淘汰；容器释放关闭 |
| 80 | 陷阱关闭；阶段仍走过 |
| 90 | 自然终局/Game End，完整边界发布 |

控制阶段的“可以开始”与结算阶段的“现在成功”分开。缓存失效后的局部检查不能重跑已经结束的 32 拾取或其他阶段。
