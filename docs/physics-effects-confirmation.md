| P04 | tick 内运动更新 | 每个逻辑 tick 固定更新运动，位移沿途做碰撞检查；碰撞求解中的接触时刻/剩余位移不另推进逻辑 tick。运动更新的递推次序、重力/阻力公式由版本化物理档案明确提供，不由渲染帧率或策略耗时决定。 |
| P05 | 求解器、同时接触与迭代上限 | 采用扫掠轴对齐碰撞盒，先定位最早接触，再处理剩余切向位移；容差内同时接触的面合并约束，候选按格坐标/盒编号稳定排序。求解迭代有显式上限，超限保守停止剩余位移并记录诊断，不能放行穿透。 |
| P06 | 承载、离地与普通起跳 | 脚底接触承载面且水平投影有正面积重叠才算承载，纯边/角接触不承载；grounded 从地形和接触派生，可缓存但不另立真值。普通起跳需承载，不允许空中重复起跳；B 保留受规则约束的空中水平操控。 |
| P07 | 击退的合成、连续受击与撞墙 | 水平击退独立保存，按本节后的受限合成方案与主动速度合成；连续受击的水平冲量向量相加并按档案限幅。碰撞移除指向障碍内部的残余水平击退分量，保留切向分量继续衰减。竖直运动只保留一份总速度，起跳/重力/竖直冲量的应用方式由档案定义。 |
| P08 | 地形变更和非法重叠 | 放置前检查保护区、空间和所有存活玩家的碰撞体，造成实体穿入则失败且不扣方块；移除承载地形后本 tick 重查支撑，B 下一运动阶段开始下落，A 在本 tick 死亡阶段结算失去承载。初始化/快照存在真实非法穿透时拒绝载入并报告，不能用容差或任意传送掩盖错误。 |
| P09 | A 与 B 的实验边界 | A 先支持平面移动/击退/碰撞及不依赖高度的已定义效果；沿运动路径首次失去承载时提交虚空死亡请求，在死亡阶段结算，这是 A 的明确简化。B 用真实竖直运动，到配置死亡高度才判虚空。A 暂不开放普通跳跃、跳跃药水、自动跨台阶、蹲伏防坠、水/梯子、火球跳及珍珠；实验配置和商店明确排除，不能扣物后空操作。 |
| P10 | 战斗与其他空间查询的接口 | 距离、遮挡和命中查询使用真实碰撞几何：A 用实验平面，B 使用三维空间；固定顺序打破完全相同的候选优先级。完整近战选择/朝向角度、护甲、投射物和爆炸矩阵转入后续战斗阶段，不在本阶段暗中补默认规则；本模块接收经校验的伤害/冲量，并保留效果与归因挂接位置。 |

P07 已接受的合成方案是本项目在“击退占主导”约束下的具体建模选择，不是已测得的 Hypixel 算法：

- 显著击退存在时，令水平击退为 k、大小 K、单位方向 n，主动速度为 a。反向主动分量最大只能减去 `alpha * K`，其中 `0 <= alpha < 1`；顺向分量保留，侧向主动分量限幅为 `beta * K`，其中 `0 <= beta <= 1`。
- 因此主动反向输入不能让合成运动沿 n 的分量停止或反转；新的敌方冲量可以改变击退向量。
- K 低于独立的速度判零/恢复控制阈值后清零残余击退，恢复普通主动运动。`alpha`、`beta`、阈值、连续受击上限与衰减模型必须在物理档案中明确给定、标注证据或实验来源；缺值不自动取零。
- 碰撞约束仍优先，受阻分量被移除不属于主动输入抵消击退。若后续取证表明该方案与 Hypixel 不同，保留实验档案并通过规则版本描述差异。

## 2. 已接受的药效应用方案

| 编号 | 问题 | 已接受决策 |
| --- | --- | --- |
| F01 | EffectState 的编码与来源 | effect_id 为不透明字符串，effect_type 为平台小写枚举；source 至少包含 kind/source_id，覆盖键由效果定义给出。等级为从 I=1 开始的正整数，非等级效果为 null；时间用整数 tick，非周期 next_trigger_at 为 null。有时限效果必须给出 expires_at，区域条件型来源才允许 null 并逐 tick 校验区域条件，不能用 null 代替未知时长。 |
| F02 | 属性型效果的实际作用点 | 速度只改主动移动计算，不放大既存击退；跳跃改变之后起跳的参数，不追溯修改已在空中的速度；急迫/疲劳进入拆块速度公式，不能把任意倍率乘到所有动作。团队升级从 TeamState 派生；生效属性不再独立复制为第二份真值。 |
| F03 | 效果施加与交易原子性 | 饮药/进食完成时将扣物、效果及事件一并提交；陷阱将资格复核、出队/冷却和效果/报警一并提交。启用场景前确认处理器和规则完整，不能队列已消费才发现没有效果实现；应用继续校验 player_id/life_index/实例有效性。 |
| F04 | 到期端点、刷新与等级变化 | 效果有效区间为 `[applied_at, expires_at)`，到期 tick 先失效，不在到期 tick 额外周期触发。同等级同周期刷新继续沿用已确认的下一触发时刻；等级或周期变化时替换旧实例，下一次设为 now 加新周期，不立即额外触发。 |
| F05 | 多来源的周期效果 | 同种再生按生效等级选择一个来源，平级按稳定来源键选择；被压制来源的时钟继续推进且不产生回血，恢复时不补发积压次数。不同机制的周期治疗是否并存由明确规则表配置，缺少合并定义就不启用该组合，不能从速度/急迫的合并推导吸收或全部治疗。 |
| F06 | 治疗与吸收生命 | 普通生命/吸收采用有限的 binary64 数值，治疗至多到当前上限，不复活已死亡玩家；吸收余量仍只在 vitality 保存一次。效果记录来源/时限/控制实例，不另存重复余量；具体补充/覆盖/到期扣除行为按核验后的规则执行，过期旧实例不能清掉新实例授予的吸收。 |
| F07 | 隐身和致盲的二维应用 | 隐身只改变观测和暴露线索，实体仍参加碰撞、命中及交互；本人/队友识别与敌方隐藏分别处理。A 的致盲采用缩小感知范围的显式实验适配，半径由实验档案给定；未完成观测过滤前不开放相关效果。错误、合法动作提示、奖励等也遵守同一隐藏信息边界。 |
| F08 | 陷阱受体、区域效果和牛奶 | core 根据地图/存活状态/效果规则计算受体，策略不能声明资格。Blindness/Fatigue/Reveal/Counter 各自有明确的受体、范围、施加/报警处理器；牛奶按逐陷阱交互表决定资格、报警和队列消耗，不用一个笼统免疫开关猜测。Q15 与未知交互继续保留核验状态。 |
| F09 | 区域来源的进入与离开 | 区域效果依据移动后的真实位置和当前地图/队伍规则更新；进入时建立该来源，离开时移除区域来源，保留其他独立来源。条件型周期效果首次进入等待完整周期，离开清除其计时、再次进入重新等待；不在 TeamState 复制玩家临时效果。此为模拟推荐，需记录与原规则的吻合或差异。 |
| F10 | 与全局时序衔接 | 保留 0012 已定阶段相对顺序，新增 35 区域来源、45 交互完成/效果施加、55 周期效果阶段；后续 W09 已补 0 地面物品到期、25 生成和 32 拾取，见下表。新效果不追溯重算已结束的移动，治疗在本 tick 伤害之前结算；同刻刷新/触发按这些阶段确定。当前调度代码尚未修改。 |

候选效果目录覆盖 speed、jump_boost、invisibility、haste、mining_fatigue、blindness、regeneration、absorption、magic_milk 及保护类状态；这不是把所有效果默认启用。持续区域来源、瞬时揭隐/报警与保护可以采用专用处理器，不能为了统一字段而伪造等级、持续时间或周期。

F05 与 F09 是本项目已接受的周期来源管理方式，尚未证明与 Hypixel 全部回血机制相同；来源组合、区域进入时点等仍需 R06 核验。若取证不同，正式 Hypixel 档案应记录修订，实验档案不得改名冒充实测规则。

## 3. 已接受的 tick 时序设计

本表是用户已接受的平台确定性约定，不是 Hypixel 服务端内部时序。原有阶段来自 0012，35/45/55 来自 P/F/V；后续 [W09](decisions/0013-world-engine-and-state.md) 已补入 25/32 并扩展 0 的地面物品到期清理。当前运行代码仍只有 0012 的阶段枚举，25/32/35/45/55 及完整处理器尚待后续实现，不能将设计确认写成代码已支持。

| 顺序 | 阶段 | 说明 |
| --- | --- | --- |
| 0 | 效果与地面物品到期 | 效果按原规则失效、旧实例事件校验后丢弃；清理本 tick 已到期的地面物品，使其不再参与后续积累统计/拾取 |
| 10 | 复活 | 保留已取得的本次复活资格，构造新生命 |
| 20 | 控制更新 | 按 W08 转向→手持切换→移动通道更新→交互通道更新；取消占对应通道更新位置 |
| 25（W09 新增） | 资源生成 | 到期且仍有效的任务提交新掉落物与后续生成计划 |
| 30 | 运动与碰撞 | 使用此前已生效的属性；玩家、物品与独立实体按 A/B 规则运动碰撞，之后按 0014 保守合并合格地面物品 |
| 32（W09 新增） | 地面拾取 | 读取运动后的最新状态，按 0013 的普通拾取与生成器分享规则逐笔结算；具体范围/延迟数值与处理器待落实 |
| 35（新增） | 区域来源更新 | 按移动后位置处理区域进入/离开，派生条件型效果 |
| 40 | 购买 | 按已定顺序重查资格、资源与报价，可使用本 tick 32 阶段刚拾取的资源 |
| 45（新增） | 交互进度/完成与效果施加 | 饮药、进食、拆建、容器存取和独立实体创建/地形变化按规则处理；成功扣物及结果原子提交，地形变更后重查支撑 |
| 50 | 破床 | 仍先于同 tick 死亡 |
| 55（新增） | 周期效果 | 处理仍有效且本次应触发的来源；刷新替换实例时不重复触发 |
| 60 | 伤害与死亡 | 处理经验证的伤害及 A/B 虚空死亡请求 |

| 90 | 对局结果 | 标准对战按 W10 的仍可参赛队伍数判胜/平/继续，单队训练按任务规则判成败；随后生成完整边界观测，Runner 检查外部时限；赛程调度结构已采用，具体事件阶段另定 |

由此，45/80 阶段获得的速度效果从下一运动阶段开始影响位移；55 阶段治疗先于 60 阶段伤害；同等级同周期刷新若在 45 阶段保留本 tick 的下一触发时刻，55 阶段仅由新有效实例触发一次。等级/周期改变则按 F04 从完整新周期等待。

25 新生成的资源可在资格通过时于本 tick 32 拾取并用于 40 购买；32 之后出现的掉落物最早下一 tick 拾取，不补跑拾取。40 Forge 升级不追溯改变本 tick 已结束的 25 生成；生成器计时/统计实验方案仍保留 Hypixel 待核验状态，投射物挂接继续随 W09 独立实体细化。

地形在 45 阶段改变后，35 阶段形成的区域来源需针对受影响对象重新校验；55/80 阶段也必须检查当前资格，不能让缓存延续已失效条件。新阶段实施时版本化调度/快照契约，旧档案不能静默改成新时序。
